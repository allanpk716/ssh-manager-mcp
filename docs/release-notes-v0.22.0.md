# v0.22.0 发布注记（草稿）

> 发版时把本文件内容作为 GitHub Release body（中文为主，与既往 release 一致）。
> 本版改动了快照内容与配对签名，**升级顺序必须是先升所有客户端，最后重启权威端**。

## 一句话

权威端可以统一管理机密项、网络拓扑与共享存储，并下发到各工作机；新增服务器软件清单登记与 CycloneDX 导出；Web UI 补齐对应页面、服务器详情反向视图与一屏配对批准；新部署的权威端证书默认改为 ECDSA P-256。

## 主要变化

- **机密项**：在权威端登记机密值，按服务器授权分组下发；命令与上传内容里的占位符在目标服务器上替换，机密值不进入 AI 上下文与审计。
- **网络拓扑**：登记站点、设备、物理与虚拟网络，Web UI 提供物理、虚拟与叠加三种视图和现场探测；手机上只读查看。手机深色模式下文字清晰可读，设备显示服务器条目名称，站点框与局域网框标出名称（未命名时显示「未命名站点」「未命名局域网」），多个空分组框不再叠在一起。
- **软件清单**：为每台服务器记录安装了哪些软件服务与支持库，供外部漏洞扫描工具使用；sshmgr 只记录，不做漏洞匹配，也不提醒。由权威端或指定工作机经 SSH 执行固定的只读命令集采集（Linux、macOS、Windows），默认不使用 sudo；Windows 上不查询 `Win32_Product`，不会触发安装包自检修复。也可人工登记声明项、确认采集草稿。`sshmgr inventory export --format cyclonedx` 导出 CycloneDX 1.6 文件；查看、搜索、采集状态与变更历史在命令行与 Web UI「软件清单」页都可用。
- **共享存储**：登记 NAS 等共享存储，按可挂载范围授权到服务器，支持现场探测、单台挂载与卸载、撤销联动卸载、安全换密码、残留检查清理；Windows 工作机可注入网络盘符，并提供桌面手动添加引导（不显示共享密码）。
- **服务器详情反向视图**：一处看到一台服务器关联的机密项、共享存储、服务器授权分组与下发记录；删除服务器前预览影响面。
- **敏感操作重新验证**：Web UI 中修改机密项、变更授权、撤销设备码与项目令牌、共享存储卸载撤销与残留清理等敏感操作，要求最近 5 分钟内重新输入管理员口令。批准与拒绝配对是例外：已登录权威端 Web UI 即可操作，防跨站请求伪造校验与审计仍保留。
- **配对批准一屏完成**：配对列表页直接显示实例名、客户端连接的权威端地址、6 位短认证码、剩余时间和 Profile 选择；勾选「我已逐位比对三项一致」后即可批准或拒绝，不用再进入单条表单，也不用重新输入管理员口令。手机浏览器同样可用。
- **本机对外地址**：新设置项 `serve.public_addresses` 可登记端口映射、反向代理或容器网络里的对外地址。格式是英文逗号分隔的「主机」「主机:端口」「[IPv6 地址]」或「[IPv6 地址]:端口」；只写主机时任意端口都算本机，写了端口时端口必须相同；环回地址（如 127.0.0.1、localhost）不能登记。例如端口映射部署执行 `sshmgr settings set serve.public_addresses 172.18.200.47:18178` 后，配对不再把 `https://172.18.200.47:18178` 判成异常地址。陌生地址在 Web UI 中只给拒绝按钮，后端也会拒绝批准；确属受控中继时仍可在权威端主机用命令行 `serve pair approve --allow-foreign-url` 显式放行。
- **主机密钥锚记录算法**：`servers pin-hostkey`、服务器详情显示锚的密钥算法；连接时按锚的算法收窄协商。
- **备份**：加密备份的导出与恢复只在权威端主机命令行执行，Web UI 只查看状态与校验。

## 升级提示

- **先升所有客户端，最后重启权威端。** 权威端按客户端声明的版本裁剪快照：仍为 v0.21.1 的客户端拿不到机密项、共享存储与网络盘符。
- **旧客户端（v0.21.1）配对新权威端**：新部署的权威端证书为 ECDSA P-256 时，旧客户端的配对申请会被提前拒绝并提示升级。先升级该工作机的客户端；临时办法是 owner 在权威端执行 `sshmgr cache-tokens add` 发放设备码，再在那台工作机执行 `sshmgr cache pull` 入网。证书仍为 ed25519 的旧部署不受影响。
- **旧客户端（v0.21.1）连接同时提供 ECDSA 与 ED25519 主机密钥的服务器**：若该服务器的主机密钥锚是 ED25519，旧客户端会误报「host key mismatch: possible MITM」并拒绝连接。这是旧版本客户端的限制，不是真的遭到中间人攻击。处理办法：先升级这台工作机的客户端；升级前可临时把该条目的锚改为 ECDSA 指纹。
- **新客户端连接旧权威端（v0.21.1）**：带机密项的操作在连接前整体拒绝，网络拓扑与共享存储入口提示权威端版本过旧；未锚定条目首次连接会自动改用旧格式转发主机密钥锚。
- 完整混布矩阵见 [docs/compat-matrix.md](./compat-matrix.md)。

## 已知问题

- **Windows 桌面手动添加共享存储**：这台电脑已用其他账号连接过同一台共享存储设备时，Windows 会报错 1219。引导页已提示先执行 `net use \\<地址> /delete` 断开既有连接，或改用该设备的其他地址。桌面手动映射、写入读取与断开三步本版未完成真机验证，安排到下个版本补测。

- **软件清单导出中的未识别进程与 Windows 服务没有版本号**：这类条目来自正在运行的进程或服务，本身拿不到版本，CycloneDX 中省略 `version` 字段（规范允许）。
