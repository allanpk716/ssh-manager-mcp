# 命令策略:严重后果兜底的护栏,规则权威端统一管理、随快照下发、客户端执行

agent 经 exec_command / exec_background 下发的命令可能因误解、路径拼错、变量为空(`rm -rf $DIR/` 在 DIR 为空时等于 `rm -rf /`)造成不可恢复的损失或把自己锁在门外。我们决定:**引入命令策略,只识别严重后果(格式化、直接写磁盘、删除根目录或系统关键路径等一律拦截;锁在门外、整卷或整池销毁、删除目标在执行前无法确定的递归删除三类需确认),其余一律放行;规则由权威 vault 统一管理(程序内置默认规则 + owner 自定义规则 + 按编号停用默认规则),随快照下发,客户端只读并在执行前就地检查**。多机部署下命令本就由客户端机器持缓存凭据直接发起 SSH,检查只能落在执行发生的地方。

它是**护栏,不是安全边界**:防的是 agent 误操作,不防有意绕过(编码后解码执行、先上传脚本再运行、换用 python 等解释器删除文件——写法无穷,任何命令规则都挡不住)。这与 backlog「明确不做」中的「命令过滤」不矛盾:那一条的目的是对 agent 隐藏服务器地址,因不可行且杀死可用性而否决;本条目的不同,且只承诺兜底,不承诺全面。

## Considered Options

- **全面风险评估(普通递归删除、卸载软件包、重启、`curl | sh` 等都需确认;命令含变量即需确认)**:被否——日常命令到处是变量,需确认频繁触发,每次多一轮工具往返,token 与逻辑复杂度都失控;定位收窄为严重后果兜底。
- **只在权威端检查**:被否——多机部署下执行不经过权威端,权威端看不到命令。
- **按服务器区分规则**:暂不做——第一版全局一套,复杂度换不来足够价值。
- **需确认用布尔开关**:被否——agent 可每次预先带上开关使确认失效;改为一次性确认码(与命令完整文本 + 服务器绑定,5 分钟有效,用一次作废),额外 token 可忽略。

## Consequences

- **不同 shell 精度不同(如实承认)**:POSIX shell 按语法拆解;PowerShell 与 cmd 无可用解析库,只做粗略分段 + 命令名(含别名、不区分大小写)匹配,动态执行写法判需确认。服务器条目需标注 shell 类型(默认 POSIX)。
- **旧版客户端静默失效**:不认识规则的客户端照常执行一切命令;因定位是护栏而接受,只在诊断面让它可见。
- **默认规则内置在程序里**:即使快照尚无策略数据,默认规则照样生效;升级程序即升级默认规则。
- agent 看不到规则清单,被拦截时只拿到一行「规则编号 + 为什么危险 + 该怎么做」。
