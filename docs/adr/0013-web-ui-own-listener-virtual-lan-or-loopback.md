# 权威端 Web UI 使用独立监听,只绑虚拟局域网地址与回环地址

ADR 0010 原定权威端 Web UI 挂在 `serve` 的 `/ui` 下。但 `serve` 只有一个监听地址,客户端拉快照、配对都要经它从物理局域网访问;owner 只打算在虚拟局域网里使用 Web UI,不希望物理局域网上的其他人能访问到管理界面。我们决定(2026-10-31 grilling 定案,地图「局域网共享存储、网络拓扑与 Web UI 管理界面」的票「Web UI:前端技术选型」):

1. **Web UI 另开端口、独立监听**,路径前缀仍为 `/ui`;`serve` 的主监听不再提供 `/ui`(返回 404),快照与配对等客户端接口不受影响。
2. **监听地址默认自动推导**:取拓扑数据里权威端所在设备在各虚拟局域网中的成员地址,与本机网卡上实际存在的地址取交集,全部监听;owner 可用设置项 `serve.ui_listen` 手动指定以覆盖。不按网卡名或网段猜测虚拟局域网。
3. **`127.0.0.1` 始终监听**,作为本机加 SSH 端口转发的救急入口,不增加暴露面。
4. **虚拟局域网地址暂不存在时**(例如开机时虚拟局域网客户端尚未启动)每 30 秒重试绑定并写日志;拓扑中的虚拟局域网成员地址变化时重新计算,关旧开新。
5. **单机与客户端的 `sshmgr ui` 仍只听回环**:它们只靠一次性启动令牌换会话、没有管理员口令,单机模式又有全部写权限,不对网络开放;远程管理一律经权威端 Web UI。

## Consequences

- 修订 ADR 0010「权威端:`serve` 的 `/ui`」:改为 `serve` 进程内的独立监听;在权威端运行 `sshmgr ui` 打印的是这个独立监听的地址。
- 同一虚拟局域网里的其他设备仍能连到该端口,管理员口令、按 IP 锁定、自签证书指纹比对等鉴权措施照旧,不因只绑虚拟局域网而放松。
- 会话 cookie:权威端 `Secure` 加 `__Host-` 前缀;回环模式的 cookie 名带端口号,避免同一台机器上两个 `sshmgr ui` 的同名 cookie 互相覆盖(浏览器的 cookie 不按端口隔离)。
