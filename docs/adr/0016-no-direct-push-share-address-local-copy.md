# 不新增服务器之间直接推送;中继一端是共享地址时改在可挂载的服务器上经挂载本地拷贝

中继(`relay_file`)的字节经过执行这次工具调用的那个 sshmgr 实例的内存。执行实例不和源、目标同在一个物理局域网时(例如 agent 在笔记本上,源和目标都在公司 A),字节先下行到执行实例、再上行到目标,绕两遍远路。我们决定(2026-10-31 grilling 定案,地图「局域网共享存储、网络拓扑与 Web UI 管理界面」的票「大文件直传:是否新增机器 X 直接推送到机器 Y 的传输方式」):

1. **不新增机器 X 直接推送到机器 Y 的传输方式。**
2. **共享地址是指称共享存储内文件的唯一写法**:`\\<主机>\<共享名>\<子路径>`(`smb://` 写法等价),`<主机>` 是提供方设备任一网络成员的地址,只用来认出共享存储;「主机 + 共享名」对上多个时报错列候选。翻译成某台服务器上的实际路径按挂载点约定,实际挂载地址仍按既定选址规则(在目标服务器上按共同网络、物理局域网优先探测)动态决定。
3. **中继一端是共享地址时,在可挂载该共享的那台服务器上经挂载做本地拷贝**:sshmgr 后台任务保持一条 SSH 会话执行拷贝(Windows 在会话开头注入 `net use`,用 `robocopy`;Linux 与 macOS 用 `cp`),先写 `<目标>.sshmgr-partial`、完成后改名;不续传,断开即从头重跑;进度与停止复用传输任务。另一端不可挂载时退回流式中继,由一台已挂载该共享的服务器作共享地址那一端;这样的服务器有多台时,优先与提供方同在一个物理局域网的,并列时按服务器名字排序取第一台,agent 可用可选参数 `via` 指定。共享地址在源端或目标端对称处理;两端都是共享地址时直接报错,提示在可挂载的服务器上用 `exec_command` 拷贝,实际路径从拓扑的按需查询接口取得。
4. **`exec_command` 不改写命令文本里的共享地址**;由拓扑的按需查询接口给出「共享地址 + 服务器 → 实际路径与是否在可挂载范围内」。

否决的做法:
- **SSH 代理转发,在 X 上运行 `sftp`/`rsync` 推到 Y**:会话期间 X 能使用这把私钥;续传要另起一套,接收端块清单用不上;整个版本四个功能一起发布,新增传输方式拉长周期。
- **一次性密钥写进 Y 的 `authorized_keys`,传完删除**:改动服务器授权文件,失败时残留风险最大。
- **中继按拓扑在返回中附「绕路较慢」提示**:给中继增加对拓扑的依赖;agent 已能用拓扑查询接口自行判断。

## Consequences

- 两端都不能挂任何共同共享存储(例如离线服务器不允许挂 NAS)时,仍只能绕经执行实例,这一缺口有意接受。
- 本地拷贝不续传,与流式中继的块清单续传语义不同:同一个工具里存在两种断开后的行为,返回结果要写明走的是哪一种。
- Windows 上的本地拷贝依赖 sshmgr 一直开着那条会话;执行实例退出,拷贝随之中断。
