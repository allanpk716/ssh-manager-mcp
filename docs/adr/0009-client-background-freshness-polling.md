# 客户端快照保鲜:从「只在调用时检查」改为后台轮询版本号,并以变更提示告知 agent

此前多机客户端的快照只在桥启动时和工具调用发现超过有效期(默认 30 分钟)时保鲜,权威端的修改最长要等一个有效期才被客户端看到,agent 也无从得知发生了变化。共享存储换密码、服务器增删、命令策略调整之后,agent 若仍按旧信息操作就会出故障而不自知。我们决定:**权威端为快照维护版本号,并新增一个只返回版本号的轻量查询接口;每个桥启动后台定时器(默认 5 分钟,可配置)查询版本号,变了才拉取全量快照;同一台机器上多个桥共用同一份缓存文件,一个桥拉到后其余桥发现文件变新即重新读取。共享存储、服务器增删、命令策略的变化,以变更提示的形式附在 agent 下一次调用任意 sshmgr 工具的返回结果开头,同一会话每条只提示一次,永不包含机密项的值**。单机部署不启用定时器,每次工具调用时比较本地 vault 的版本号即可。

## Considered Options

- **维持只在调用时检查**:被否——变化最长滞后一个有效期,且 agent 不知道变了。
- **每次轮询都拉全量快照**:被否——同一台机器上可能并存多个桥,全量拉取的流量和权威端负载随会话数线性增长。
- **通过 MCP 主动推送消息告知 agent**:被否——agent 宿主(Claude Code)不会把服务端主动推送的消息交给模型,只有工具返回结果一定会被模型读到。
- **客户端在后台自动更新服务器上的挂载**:被否——后台悄悄修改服务器,出了问题无从追查;改为由变更提示指明需要更新的服务器,交给 agent 调用幂等的挂载工具完成,每一步都有审计。

## Consequences

- 权威端新增一个接口,旧版客户端不会调用它,行为与以前相同。
- agent 若一直不调用 sshmgr 工具就收不到提示;这种情况下它也没有在操作服务器,可以接受。
- 离线时仍停在旧快照上照常工作,与以前一致。
- `docs/multi-machine.md` 中「保鲜只在调用时进行」的描述需要随实现改写。
