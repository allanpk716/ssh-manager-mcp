# 主机密钥的锚跟随服务器条目,所有候选 SSH 地址共用一把;自动首次锚定优先只经虚拟局域网地址

网络拓扑让一台服务器有了多个候选 SSH 地址(它所关联设备的各个网络成员地址,加上兜底的 `Host`),而且明确允许不同网络使用相同网段。原先锚的归属键是「主机:端口」且全局唯一,这在多地址下站不住:家 A 的工作机 1 和家 B 的工作机 2 都可以是 `192.168.1.10:22`,全局只能存一把锚,后锚定的那台永远报密钥不一致;同一台机器换个地址连,又会被当作从未锚定。我们决定(2026-10-31 grilling 定案,地图「局域网共享存储、网络拓扑与 Web UI 管理界面」的票「主机信任:多地址下的主机密钥锚定」):

1. **锚跟随服务器条目**:每个条目一把锚,它的全部候选 SSH 地址共用(先例是 OpenSSH `HostKeyAlias`)。条目改地址、改端口、改网络成员时锚保留不动;新地址上若是另一台机器,连接报密钥不一致,由 owner 用 `--force` 覆盖或 `--clear` 删除。删除条目时它的锚在同一事务里一并删除并写审计,此后不再产生孤立锚。不受管设备(例如只提供共享存储的网络附属存储)不涉及锚;SMB 服务端身份校验不在本版范围。
2. **按序试连遇到密钥不一致就跳过**:主机密钥校验先于发送登录凭据,跳过不泄露凭据。不一致的地址不进「10 分钟成功地址缓存」,命令结果附一行「地址 X 呈现了不同的主机密钥,已跳过」;全部失败时错误逐个列出各地址的结果。
3. **自动首次锚定优先只经虚拟局域网地址**:条目有虚拟局域网地址时,首次连接即信任与锚定转发都只经虚拟局域网地址进行;物理局域网地址可连通但条目尚无锚时,这次改走虚拟局域网地址完成锚定,之后物理局域网地址共用这把锚。条目根本没有虚拟局域网地址时维持原语义,任何地址都可首次锚定。
4. **锚定转发协议**改为携带「条目 ID + 握手所用地址 + 密钥」。权威端检查:条目在设备码绑定的轮廓内;该条目尚无锚(仅可新增,原子落库);握手地址是该条目的候选地址之一;条目有虚拟局域网地址时握手地址必须是虚拟局域网地址。握手地址写进审计与锚的来源信息。
5. **owner 入口**:`servers pin-hostkey <name>` 形式不变、对象改为条目;`--list` 按条目列出并显示锚是经哪个地址学到的;删除 `--clear --hostport` 孤立锚形式。Web UI 服务器详情页显示锚的指纹、来源与锚定时间,覆盖与删除属敏感操作,要求 5 分钟内重新输入管理员口令。
6. **存量迁移**:每一行「主机:端口」锚复制给所有 `Host:Port` 与之相同的条目(同一台机器的多个登录用户条目各得一份);没有任何条目指向的孤立锚丢弃,写一条迁移审计列出被丢弃的锚及指纹。导入旧版本快照或备份时走同样的迁移。
7. **新旧客户端混跑**:新快照在按条目的锚之外,为每个条目的兜底 `Host:Port` 额外生成一行旧格式锚,旧客户端连兜底地址照常校验;新权威端收到只带「主机:端口」的旧格式转发请求时拒绝并提示升级客户端,不去猜它对应哪个条目。
8. 同一把密钥出现在多个条目上(克隆的虚拟机常见)不拦截、不提示。
9. **同一设备上兄弟条目之间复制锚**(2026-10-31 补充,票「网络拓扑:同一台机器多个服务器条目与设备的对应关系」):设备放宽为可关联多个服务器条目后,条目挂到设备上(新建或从别的设备移入)时若尚无锚,而该设备上有端口相同、已锚定的另一个条目,就复制那把锚,写审计并在锚的来源信息里记「复制自条目 X」;已有锚不覆盖,端口不同的条目(例如容器里另起的 SSH 服务)不复制。条目误挂到错的设备时,复制来的锚只会让连接报密钥不一致而跳过,不会把凭据交给错的机器。

## Considered Options

- **保持按「主机:端口」锚定,锚定一次时把同一密钥写给该条目的每个候选地址**:被否——不同网络网段重复是合法拓扑,全局唯一的「主机:端口」键注定让其中一台无法锚定。
- **任何地址都可首次锚定**(原语义):被否——笔记本在家 B 按序试连可能先连到家 A 地址在家 B 上的另一台机器(走错门);若此时条目尚无锚,就会把错的机器锚成目标,之后凭据会交给错的机器、agent 的命令也在错的机器上执行。虚拟局域网地址在全网唯一、身份由虚拟局域网自身认证,走错门的可能性远小于物理局域网。
- **首次锚定时试遍所有可连通的候选地址、要求密钥一致**:被否——首次连接变慢,且只能连通一个地址时仍无法分辨走错门。
- **按序试连遇到密钥不一致立即整体失败**:被否——会让「不同站点网段相同」的合法拓扑在另一站点每次都失败,违背按序试连的初衷。
- **条目改地址时自动清除锚**:被否——会悄悄重新打开一次首次连接即信任的窗口。

## Consequences

- 修订 ADR 0002 的后果「锚按『主机:端口』全局唯一,同地址其他轮廓的条目同样继承被预置的锚」:预置投毒的效果从「全局按地址」缩小到「单个条目」;设备失窃清毒流程中的 `--clear` 改为按条目粒度。ADR 0002 的「转发永不覆盖、owner `--force` 唯一覆盖、`--clear` 唯一删除」三级权威性不变。
- 权威端对握手地址的两项检查(是候选地址、有虚拟局域网地址时须为虚拟局域网地址)挡不住故意说谎的设备码持有者,只拦出错或版本不一致的客户端;如实承认。
- 条目没有虚拟局域网地址、又被只在另一站点有相同网段的笔记本首次连接时,走错门锚定的风险与原先相同,没有消除。
- 锚的存储、快照格式、转发请求格式都是跨版本协议的变化;旧格式锚只为兜底 `Host:Port` 生成,旧客户端经网络成员地址连接时得不到多地址的好处。
- 设备已放宽为可关联多个服务器条目(见第 9 条),锚仍跟随条目,同一台机器的多个条目各有一把,端口相同时经复制得到同一把密钥。
