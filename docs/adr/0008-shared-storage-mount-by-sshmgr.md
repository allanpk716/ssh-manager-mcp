# 共享存储:由 sshmgr 代为挂载,密码沿用机密项,不让 agent 自己拼挂载命令

多台受管服务器需要共用局域网或虚拟局域网里的网络共享(首版只做 SMB)存放大数据和临时数据,过去每台机器都要 owner 手工配置连接。我们决定:**owner 在权威 vault 登记共享存储(访问地址、共享名、目录约定、挂载点约定),挂载账号的密码存为机密项;sshmgr 提供挂载工具,按目标服务器的操作系统自己生成并执行持久挂载(Linux 写仅 root 可读的凭据文件和 `/etc/fstab`;macOS 写 autofs 间接映射;Windows 在每条命令执行前于同一会话内注入 `net use`——见下文「各系统的挂载方式」),密码由 sshmgr 在内部填入,不经过 agent 上下文**。能挂载哪些服务器,沿用该机密项的「可写入服务器列表」,列表内无需逐次确认。

## Considered Options

- **只登记,由 agent 自己执行挂载命令、sshmgr 代填密码**:被否——Windows 的 `net use` 和 `cmdkey` 必须在命令行里带密码,这会逼着机密项去支持命令行代填,扩大机密项的安全面(命令文本会进入命令策略检查、审计日志)。
- **不挂载,sshmgr 自己连接共享,用中继在共享和服务器之间搬文件**:被否——大数据全部经过 broker 内存中转,成为瓶颈;而且服务器上的程序无法把共享当作普通目录使用。
- **另设一份「可挂载服务器名单」**:被否——挂载本质就是把密码写进那台服务器,与「可写入服务器列表」含义相同,两份名单迟早不一致。

## Consequences

- 挂载工具必须幂等(已挂载且配置一致即成功;写远端配置时加文件锁),因为多个会话、多台客户端机器可能同时挂载同一台服务器。
- agent 只能挂载,不能卸载:挂载被一台服务器上的所有会话共用,卸载会打断其他会话,所以卸载只在 owner 的命令行和 Web UI 里提供。
- 权威端不记录各服务器的挂载状态,唯一事实源是服务器本身;改密码后的「重新下发」与「已移出列表但仍挂载」检查都靠逐台现场探测。
- 只收能持久挂载的协议;FTP 这类有会话数限制、空闲会被断开的协议不进入此机制。
- **多个 sshmgr 进程并发**(每个 agent 会话一个桥进程,多台客户端机器同时操作同一目标):挂载工具不改写仍可连通的地址(改地址等于卸载再挂载,会让 agent 间接获得卸载能力),切回更优地址由 owner 在 Web UI 触发;目标机上的挂载配置带共享存储版本号标记,快照落后的进程不得覆盖(只适用于 Linux / macOS,Windows 目标机上不留标记);Windows 注入遇认证失败即暂停,直到该共享版本号变化,避免旧密码反复尝试触发 NAS 按 IP 封锁;登记共享存储的前提是关闭 NAS「禁止同一 IP 多个连接」开关。
- **撤销**(owner 取消某台服务器的授权):可写入服务器列表的变化也让共享版本号加一。Linux / macOS 先删凭据与挂载配置、留下不含密码的撤销标记(挡住旧快照进程重新写入),再卸载,占用时由 owner 决定是否强制;服务器连不上不排队,靠「检查残留」现场检测兜底。Windows 撤销就是停止注入,随快照同步生效,离线客户端在同步前仍会注入——护栏而非安全边界;真正的撤销手段是改共享密码。

- **挂载在整台机器上可见**(2026-10-31 补充):可挂载范围按服务器条目登记,但一台设备可关联多个条目(同一台机器的不同登录用户),挂载发生在机器上;同设备上未勾选条目的登录用户能否读到共享内容取决于挂载的文件权限,sshmgr 不按登录用户隔离。Web UI 共享详情页勾选条目时,若同设备还有未勾选的条目,提示「同设备的其他条目可能也能读到」。
- **删除提供共享存储的设备**(2026-10-31 补充):不再拒绝,改为级联删除——设备上的共享存储一并删除,对可挂载范围内每台服务器走上面的撤销流程;挂载密码机密项保留,真正撤销仍靠改密码。删除前的预览按共享存储逐项列出可挂载范围内的每台服务器(条目名、所属设备、系统类型),即撤销流程将去卸载或停止注入的机器;因挂载状态不留记录,列的是范围而非已挂载的现状。

## 各系统的挂载方式(2026-10-31 补充,依据真机验证)

- **Linux**:`/etc/fstab` + 仅 root 可读的凭据文件,选项含 `_netdev,nofail,x-systemd.automount` 与 `x-systemd.mount-timeout`;SMB 协议版本由挂载工具在目标机上按 3.1.1 → 3.0 → 2.1 → 2.0 依次试出后写入,不作登记字段、不回写权威端。
- **macOS**:autofs **间接映射**挂在 `/mnt/sshmgr`,密码按 URL 编码写进权限 600 的映射文件。不用 LaunchDaemon:间接映射免建目录、抗重启、无人登录可用。系统升级可能重置 `/etc/auto_master`,不做主动监控——现场检测发现条目缺失即报告未挂载,挂载工具每次调用都重建配置。
- **Windows**:密钥认证的 SSH 会话是网络登录,无法存凭据,每次执行命令又是新的登录会话,不存在「配置一次、此后会话自动可用」的做法(计划任务、SYSTEM 账户路线均经真机证伪)。因此 sshmgr 在**每条命令执行前于同一会话内注入** `net use <盘符>:`,对目标机所在可写入服务器列表内的全部共享存储自动注入,不在服务器上留任何东西;不需要、也不索取 Windows 登录密码。注入失败不阻止命令,只附警告;注入内容不进审计、不进命令策略检查。挂载点约定是 owner 登记时为每个共享存储指定的固定盘符(同一 vault 内不重复),不含地址。代价:桌面会话、服务、计划任务、SFTP 文件传输和命令结束后仍在运行的后台进程都看不到这个盘符;owner 自己的电脑改由 Web UI 的桌面手动添加引导解决。
- Linux 与 macOS 的挂载点约定统一为 `/mnt/sshmgr/<共享名>`。

### 被否的 Windows 候选

- **计划任务代存凭据**:免密码变体能把凭据写进凭据管理器,但 SSH 会话枚举不到、也用不上;带登录密码的变体存的凭据同样在交互侧。还要索取 Windows 登录密码,得不偿失。
- **`C:\sshmgr\<共享名>` 目录符号链接**:需要管理员权限,链接目标含地址、地址一变就要重建,且在服务器上留下持久文件;盘符不含地址、无需探测即可推算。
