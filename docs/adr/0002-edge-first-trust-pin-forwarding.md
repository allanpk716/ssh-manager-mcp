# 边缘首信:锚定转发让「仅缓存客户端可达」的目标完成首次信任

拓扑死锁:目标只有某台缓存客户端可达时,握手能力与写权限分属两侧(首次信任需要二者合一),体系内无闭合路径(v0.14.0 实测反馈;临时端口桥接因锚的归属键是「主机:端口」,条目改回真实地址后锚必然失联)。我们决定:**持有网络路径的缓存客户端完成首次信任的握手,新锚经设备码认证、仅可新增、全审计的变更落入权威 vault**(锚定转发);owner 命令 `servers pin-hostkey`(指纹/密钥扫描文件两种输入)是人工带外通道,`--force` 是唯一覆盖入口。转发的信任水位不高于现状:在线首次信任本就是无人复核的自动锚定,设备码本已能拉取其绑定轮廓的全部凭据明文,仅可新增的锚是更小的权限;投毒既有锚被「仅可新增」封死,投毒未锚目标与经典首连中间人风险同级。

## Considered Options

- **只做带外锚定**:被否——仪器调试等高频场景的诉求本体是零仪式,纯人工通道把每次新设备变成 owner 手工流程。
- **本地可写覆盖层**(类 git「本地提交、稍后推送」):被否——破坏多机同步的零合并约束,引入本地可变状态与合并语义,复杂度最高而价值被「转发+带外」全覆盖。
- **跳板首连**(broker 经一台已录入 vault 的跳板机穿隧道直连目标、在 broker 侧首信):被否——要求路径持有机可被 SSH 登录且录入 vault(本场景等于给笔记本装 sshd),信任面零扩张但一次性基建成本高;通用跳板能力独立立项。

## Consequences

- serve 的设备码可达面从「只读快照分发」扩展为「含一个仅可新增的变更」——护栏(目标条目须在该设备码绑定轮廓内/仅可新增/审计/吊销即断)是对面收缩的补偿。
- 锚格式双模(密钥字节|指纹串)成为跨版本协议:快照导出/导入、known_hosts 序列化方都需认知指纹锚不可序列化。
- 「转发永不覆盖、owner `--force` 唯一覆盖」构成权威性的两极:设备可增不可改,owner 可改。
