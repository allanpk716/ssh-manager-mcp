# 边缘首信:锚定转发让「仅缓存客户端可达」的目标完成首次信任

拓扑死锁:目标只有某台缓存客户端可达时,握手能力与写权限分属两侧(首次信任需要二者合一),体系内无闭合路径(v0.14.0 实测反馈;临时端口桥接因锚的归属键是「主机:端口」,条目改回真实地址后锚必然失联)。我们决定:**持有网络路径的缓存客户端完成首次信任的握手,新锚经设备码认证、仅可新增(insert-only,原子)、与审计同事务落权威 vault**(锚定转发);owner 命令 `servers pin-hostkey`(指纹/密钥扫描文件两种输入,`--force` 覆盖、`--clear` 删除)是人工带外通道,`--force` 是唯一覆盖入口且同样落审计。保密侧信任水位不高于现状:在线首次信任本就是无人复核的自动锚定,设备码本已能拉取其绑定轮廓的全部凭据明文,仅可新增的锚是更小的权限。

## Considered Options

- **只做带外锚定**:被否——仪器调试等高频场景的诉求本体是零仪式,纯人工通道把每次新设备变成 owner 手工流程。
- **本地可写覆盖层**(类 git「本地提交、稍后推送」):被否——破坏多机同步的零合并约束,引入本地可变状态与合并语义,复杂度最高而价值被「转发+带外」全覆盖。
- **跳板首连**(broker 经一台已录入 vault 的跳板机穿隧道直连目标、在 broker 侧首信):被否——要求路径持有机可被 SSH 登录且录入 vault(本场景等于给笔记本装 sshd),信任面零扩张但一次性基建成本高;通用跳板能力独立立项。

## Consequences

- **预置投毒增量(如实承认,2026-09-09 盲评指出)**:变更前,给目标植入攻击者锚需要真实的网络中间人位置(在某台机器上真握手);变更后,持有效设备码者只需 broker 可达,即可对绑定轮廓内**尚未锚定**的目标预置锚——包括攻击者自身到不了的目标(日后取得中间人位置时即刻生效,且真钥永远失去了「先被合法首连锚定」的机会窗)。补偿控制,而非消除:目标条目须在设备码绑定轮廓内;仅可新增封死既有锚投毒;落锚原子 insert-only 杜绝并发覆盖竞态;锚携带来源元数据(`pin_source`/`pin_device`),`servers pin-hostkey` 可见「谁锚的」;broker 侧权威审计(`pin-forward`);设备失窃的清毒流程 = revoke 设备码 + 逐条 `--clear` 其转发锚 + 合法重锚。
- serve 的设备码可达面从「只读快照分发」扩展为「含一个仅可新增的变更」——上述护栏是对面扩张的补偿。
- 锚格式与来源双维(密钥字节|指纹串 × 自动首信|转发|手动)成为跨版本协议:快照导出/导入需携带;known_hosts 生产序列化不存在,若未来引入须知指纹锚不可渲染。
- 「转发永不覆盖、owner `--force` 唯一覆盖、`--clear` 唯一删除」构成权威性的三级:设备可增不可改,owner 可改可删,全部留痕。
- 409 不自动重拉(恢复 = 指引拉取后重试):握手回调内嵌完整拉取会继承隔离与时间锚全套闸门,复杂度不抵收益。
