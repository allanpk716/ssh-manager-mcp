# 界面即视图:一切 TUI 能力必有命令行等价面;无人值守自动化走显式接口

> **2026-10-30 改写**:TUI 将在 Web UI 首版发布的同一版本里删除(见 ADR 0010)。本约束的对象由 TUI 改为 **Web UI**:Web UI 的一切能力必有命令行等价面。TUI 现有的 7 处命令行缺口(撤销 profile 授权、服务器页 ⚠ 视图与过滤、备份页状态区、`backup.json` 编辑、校验最新备份须给路径、导入 ssh config 后逐台补全、`role.json` 与设置存储写入)必须在该版本里全部补齐。反向只有命令行的三项里,`audit` 与 `projects disable/enable` 进 Web UI,`cache-tokens bind` 只留命令行。下文中的「TUI」按「Web UI」读。

> **2026-10-31 补充**:网络拓扑与共享存储的命令行等价面为 `sshmgr sites`、`sshmgr networks`、`sshmgr devices`、`sshmgr shares` 四个命令组,增删改与 Web UI 表单一一对应;拓扑图上拖动归类即修改网络成员,用 `sshmgr devices` 完成。唯一例外是拓扑图的布局坐标:纯排版,不提供命令行等价面(坐标随快照与备份保存,但变化不产生变更提示)。

到 v0.16.0 为止,主控台的每个操作(同步/实例切换/重配/删除/配对/设备码与 token 签发/轮换/升级)事实上都有命令行等价物,配对流程还带着 `SSHMGR_PAIR_ASSUME_SAS=1` 这一无人值守接口。我们决定把这从「事实」升为「约束」:**任何 TUI 能力落地时必须同时存在命令行等价面;需要跳过人工信任动作(如 SAS 双屏比对)的自动化,必须走显式的环境变量接口并响亮自警**。动因(2026-09-21 grilling 定案,「测试自助化」主轴):真机验收若只能由 owner 手工执行,欠账只会越滚越大——agent 能驱动命令行与 MCP 工具面,接口在,验收就能自助(验收册见 `docs/acceptance/`)。

## Considered Options

- **TUI 优先、命令行按需补**:被否——「按需」没有判据,漂移不可检;一旦某个操作只剩按键能触发,它就退化为「必须找 owner」。
- **为自动化另做一套测试后门**:被否——后门与产品面分叉,测的不是真路径;显式环境变量接口(前例 `SSHMGR_PAIR_ASSUME_SAS`)复用产品路径,跳过点单一、可审计、可自警。

## Consequences

- 新 TUI 功能的成本核算含命令行等价面;评审门把「等价面在哪」列为检查项。
- 无人值守接口是「跳过人工信任动作」的唯一合法形态,必须带警示文案;用它跑出的验收证据必须注明跳过(见验收册总则)。
- TUI 特有的行为(按键链、overlay 门)与观感不在此约束内——行为由进程内测试钉契约,观感归人工保留面(ADR 0003 的边界即验收册总则的人工保留面三项)。
