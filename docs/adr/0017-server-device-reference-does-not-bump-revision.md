# 服务器条目的所属设备引用不自增条目修订号

网络拓扑把服务器条目关联到设备，`servers.device_id` 因此成为服务器条目表的一列。ADR 0005 规定一切更新服务器条目的写路径都必须自增条目的 `revision`，并让全库快照修订号加一；本决定只保留条目 `revision` 的例外。

## Decision

**只修改 `servers.device_id` 时，快照修订号加一；服务器条目自己的 `revision` 不自增。**

网络拓扑现在随客户端快照下发，服务器条目的所属设备引用也包含在内。它变化时，客户端必须重新拉取快照，并看到网络拓扑变更提示；因此服务器条目表的快照修订号更新触发器必须比较 `device_id`。

条目 `revision` 是服务器元数据编辑的乐观锁令牌，只服务那六个描述性字段。移动服务器条目所属设备是拓扑维护，不是元数据编辑；如果它推进 `revision`，会让下一次真正的元数据编辑误报冲突。移动写路径因此只更新所属设备引用，不更新条目 `revision`。

服务器条目的其余列仍照旧执行 ADR 0005：条目写路径自增 `revision`，快照修订号触发器比较并覆盖全部导出列。`revision` 本身仍在触发器比较清单里，因为它是客户端快照携带的元数据编辑令牌；只推进这个令牌的写路径也必须让快照修订号前进。

## Consequences

- 未来给服务器条目新增导出列时，必须同步加入快照修订号更新触发器的 `WHEN` 清单；结构测试会用 `PRAGMA table_info(servers)` 对全部列做逐一核对，漏列会在测试中失败。
- 未来修改服务器条目所属设备的写路径必须保持只更新 `servers.device_id`，不能顺手自增条目 `revision`；存储层测试固定这一行为。
- 备份、导出与客户端裁剪快照都携带所属设备引用；这份例外只约束条目 `revision`，不改变备份内容的完整性。
