# 服务器条目的所属设备引用不增加修订号

网络拓扑把服务器条目关联到设备,`servers.device_id` 因此成为服务器条目表的一列。ADR 0005 规定一切更新服务器条目的写路径都必须自增条目的 `revision`,并让全库快照修订号加一;本决定把所属设备引用列为这条不变式的唯一例外。

## Decision

**只修改 `servers.device_id` 时不自增服务器条目的 `revision`,也不让快照修订号触发器加一。** 所属设备引用属于网络拓扑数据:它只进入 owner 的备份与导出文件,这一版不随客户端快照下发,也不进入变更提示。客户端看不到这个字段,就不会把它当作需要重新拉取的快照差异;它也不是服务器元数据乐观锁保护的六个描述性字段,不应该让 owner 与客户端的元数据编辑互相误报冲突。

服务器条目的其余列仍照旧执行 ADR 0005:条目写路径自增 `revision`,快照修订号触发器比较并覆盖除 `device_id` 以外的全部导出列。`revision` 本身仍在触发器比较清单里,因为它是客户端快照携带的元数据编辑令牌;只推进这个令牌的写路径也必须让快照修订号前进。

## Consequences

- 未来给服务器条目新增导出列时,必须同步加入快照修订号更新触发器的 `WHEN` 清单;结构测试会用 `PRAGMA table_info(servers)` 对全部列做逐一核对,漏列会在测试中失败。
- 未来若拓扑数据开始随客户端快照下发,必须重新评估本例外,不能沿用「客户端看不见」这个理由。
- 备份与导出继续携带所属设备引用;这份例外只说明客户端快照与修订号的行为,不改变备份内容的完整性。
