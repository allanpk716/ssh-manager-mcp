# 客户端拉快照时声明版本,权威端据此裁剪快照并下发推荐版本

客户端拉快照的请求原先只带设备码(`Authorization: Bearer`),权威端分不出客户端新旧;快照字段又是逐个显式列出的,旧客户端遇到不认识的字段会静默忽略。机密项上线后,旧客户端会把占位符字面量原样写进服务器,也不会遮蔽输出;后续网络拓扑、共享存储同样面临新旧版本混跑。我们决定(2026-10-31 grilling 定案,地图「机密项:agent 部署含敏感信息的配置而值不经过 agent 上下文」的票「机密项:旧版客户端兼容」):

1. **不设快照版本门槛,不硬拒旧客户端**:拒发快照会让旧客户端停在过期缓存上、同步不到任何服务器变更,代价大于一处配置失效;旧客户端原样写出占位符字面量的风险接受下来。机密项本就是护栏而非安全边界(ADR 0007)。
2. **新客户端拉快照时用请求头声明自己的客户端版本**;没有声明的请求一律视为旧客户端,权威端从它的快照里去掉全部机密项——旧客户端用不上这些值也不会遮蔽输出,下发只会扩大暴露面。
3. **权威端记录每台设备最近一次声明的客户端版本**,在 Web UI 设备列表与等价命令行里显示;没有声明的标「旧版客户端:不支持机密项」,供 owner 发版后核对哪些设备未升级。诊断放在权威端,因为旧客户端自己的诊断命令不认识新字段。
4. **新客户端识别旧权威端**:快照来自不支持机密项的旧权威端时,含占位符的写入在连接前拒绝,报「权威端版本过旧,不支持机密项,请先升级权威端」,而不是「名字不存在」。
5. **推荐版本**:快照里新增字段,值等于权威端自己的版本;第一版不提供手工指定,也不按设备分别设置。
6. **只提示,不自动升级**:客户端版本与推荐版本不一致时,在客户端本机 Web UI 与 `doctor`、`sshmgr` 命令行输出末尾、MCP 工具结果(每个会话一次,与变更提示相同做法)中提示;客户端比权威端新时提示「客户端比权威端新,建议先升级权威端」。替换正在运行的桥属于不可撤回动作,由 owner 触发。
7. **`sshmgr update` 默认装推荐版本**:客户端连着权威端时,不带参数的 `update` 从 GitHub 按推荐版本号下载,而不是 GitHub 最新版,避免客户端升到比权威端还新;`--version` 照样覆盖;`update --check` 同时显示推荐版本与 GitHub 最新版本。

## Consequences

- 发版顺序固定为先升级权威端、再升级客户端;反过来时第 4、6 条给出明确提示。
- 推荐版本机制只对本版之后的客户端生效;本版之前的客户端只能靠第 3 条在权威端发现。
- 单机模式只有一个二进制,不存在混跑,以上规则不涉及。
- 网络拓扑、共享存储等后续快照字段的新旧版本兼容沿用本 ADR 的版本声明与推荐版本机制(地图「局域网共享存储、网络拓扑与 Web UI 管理界面」的票「新旧版本混跑:旧客户端遇到带拓扑与共享存储的新快照」)。
