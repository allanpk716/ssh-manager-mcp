# Web UI 首版完全取代 TUI,同版删除 TUI;一套页面按本机角色开放能力

到 v0.21.x 为止,owner 的人工操作面是 TUI(主控台 7 页、客户端面板、首次运行向导)。网络拓扑、共享存储、机密项三个新功能需要图形化的人工界面(拓扑图尤其如此),Plan 42 规格 rev4 §4 早已为权威端预留了 `/ui`。我们决定(2026-10-30 grilling 定案,地图「局域网共享存储、网络拓扑与 Web UI 管理界面」):**首版 Web UI 覆盖 TUI 现有的全部能力,外加三个新功能与审计页,与新功能在同一个版本里发布,同版删除 TUI**。在那之前 TUI 只修 bug。

承载方式按本机角色区分,共用一套页面、随单一二进制发布:

- **单机**:`sshmgr ui` 按需启动,只监听本机回环地址,自动打开浏览器,退出即停;不新增常驻进程。全功能可写。
- **权威端**:`serve` 的 `/ui`(已由 ADR 0013 修订为 `serve` 进程内的独立监听,只绑虚拟局域网地址与回环地址),全功能可写,加配对批准。在权威端运行 `sshmgr ui` 不另起服务,只打印 `/ui` 的地址;例外是权威端尚未初始化(还没有 vault 或管理员口令)时,`sshmgr ui` 按回环模式临时启动向导页,完成初始化并显示提权安装 `serve` 的命令后退出。
- **客户端**:`sshmgr ui` 按需启动、只监听本机回环地址;只读查看本地快照(机密项只显示名字与备注),以本机为起点的拓扑图叠加本机探测结果并可触发探测,外加立即同步、切换实例、查看连接状态;修改 vault 的操作一律不出现,提示到权威端 Web UI 去做。客户端的探测结果因此仍只存本地、不回传权威端。

首次运行向导:单机与权威端的初始化放进 `sshmgr ui` 的向导页;客户端入网走命令行配对,权威端在 Web UI 里批准;每一步都另有纯命令行路径,供 agent 与无显示器的机器使用。

页面设计**桌面优先、手机可用**:查看类页面、配对批准、服务器列表适配手机;拓扑图编辑与长表单只保证桌面好用。Plan 42 的「手机优先」不再保留。

## Considered Options

- **TUI 冻结但保留,Web UI 作补充**:被否——两套人工界面长期并存,每个能力要做两遍或在两边漂移;owner 选择一次切换到位。
- **首版只做新功能,其余能力逐版从 TUI 迁移**:被否——与删除 TUI 冲突,且迁移期两套界面各管一半,使用者要记哪项在哪边。
- **客户端不提供任何 Web 界面,只用命令行**:被否——客户端自己的探测结果对它很重要,而探测结果不回传权威端,只有本机页面能呈现「从本机出发」的拓扑视图。
- **单机部署新增常驻服务承载 Web UI**:被否——单机部署的承诺是不需要常驻服务、不需要网络监听。

## Consequences

- 这次发版的规模包含:Web UI 全部页面、TUI 删除、TUI 现有 7 处命令行缺口全部补齐(见改写后的 ADR 0003)。
- 单机部署下手机访问不到 Web UI(只监听本机回环地址);是否允许开放到局域网由「Web UI:鉴权与访问控制」决定。
- 文档、验收册中依赖 TUI 的条目要全部迁移;老用户升级后找不到 TUI 时需要提示。
