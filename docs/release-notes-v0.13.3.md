# v0.13.3 发布注记（草稿 · Plan 46：实例管理与配对向导健壮性）

> 发版时把本文件内容作为 GitHub Release body（中文为主，与既往 release 一致）。
> 协议 / serve **零改动**——两端版本独立可升，无迁移、无 breaking。

## 一句话

配对重配（`pair --force` / TUI 重配）**不再先毁后建**，实例可以**一条命令删除**，client 面板的实例列表**一眼看懂每个槽缺什么**，配对失败的提示**如实告诉你下一步做什么**。

## 用户视角四件事

### 1. force 重配不再毁槽（原子覆盖）

此前 `sshmgr pair --instance <名> --force` 在**发起 enroll 之前**就把旧槽材料清掉——中途任何一步失败（网络断、owner 还没批、serve 拒了），旧凭据已经没了，机器处于"既旧不回、新未成"的半态。v0.13.3 起：

- **enroll 前零清理**：确认屏、enroll、等待批准任何一步失败，旧槽材料**一字不动**——最坏情况就是"没配成，照旧用"。
- **成功 = 原子覆盖**：新凭据在全部写盘+首拉成功后才整体替换旧材料（临时文件+rename，失败不留半文件）。
- `cache.config.json`（离线时效策略）**永远原地不动**；`quarantine/` 清理移到成功尾部，清理失败仅警告、下次成功时自动重清。

### 2. 实例可删：`cache instances ls` / `rm`

同机多实例（Plan 40）补齐删除一等公民，不再手工 `rm -rf` 两处目录：

```bash
sshmgr cache instances ls                  # 每行=实例名/auth·bin·meta·config/dek/缓存年龄
sshmgr cache instances rm laptop-agentA    # 输实例名确认 → 槽目录 + DEK 双根清理
```

- `ls` 纯 stat 不解密；**DEK 孤儿**与**半态槽**显式标注——出事形态一眼可见。
- `rm` 幂等可重试（失败报残留物清单，重跑即清完）；默认槽不可删（整机清空仍是 `sshmgr clear`）。
- **rm ≠ 吊销**：只删本机材料。成功输出会提醒你两件本机删不了的事：① broker 侧 `sshmgr cache-tokens revoke <名>`；② `--write-mcp` 写在槽外的 `.mcp.json` 副本请自行删除（路径未持久化，程序无从代劳）。
- **进程内互斥**：删除/force 清理进行中，并发的 pull / pair 写盘被**拒绝**（明确报错，不排队）；跨进程由原子写 + 幂等重跑兜底。

### 3. client 面板实例 picker 重做（TUI）

`[i]` 实例列表从"只有名字"升级为**状态表**：

- 每行四要素判定：`auth+bin+meta+DEK` 齐 = **完整**；缺任一 = **残缺**且行内点名缺什么（`缺 bin·DEK`）——半态槽带 **⚠** 前缀，一眼锁定事故现场。
- **★** 标当前所在槽；中文实例名列宽对齐（不再破列）。
- **`p` 重配**扩到全部具名行（残缺行恰是最需要重配的）；确认屏按槽状态分档提示 419 风险。
- **`d` 删除实例**：确认屏（双根清单+两件配套提示）→ 后台删除；删当前槽成功自动回落默认槽；失败报残留清单、不回落。
- 列表尾注如实：**完整/已配对标注为本地视角——远端吊销状态不可见**（要权威答案去 broker `cache-tokens ls`）。

### 4. 配对失败指引如实化

client **无法可靠分辨** serve 端是否已提交（传输中断 = 两态不可分辨）——所以不再给"应该没事"式的模糊安慰。finish 后一切失败（写盘/首拉/传输中断）的错误统一尾缀**双路径指引**：

> 恢复：直接重跑 `sshmgr pair --force`（或 TUI 重配）；若重跑报设备名占用（419），请 owner 在 broker 侧执行 `sshmgr cache-tokens revoke <实例名>` 后再重跑。

419 错误本身（enroll/finish 两处）也已带同样的 revoke 指引。没有「必定自愈」式承诺；按指引重跑（撞 419 先 revoke）是目前唯一的已知恢复路径，失败会再次给出同样指引。
