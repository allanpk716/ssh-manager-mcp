1. 主仓 `git pull` 对齐 origin/master；并发 agent 一律在隔离 linked worktree 干活（本仓多会话并行的既定纪律），收尾清 worktree（删前查未提交）。
2. 读本文件对应批次节 + 范围栏点名的入口文件。
3. 完成动作（每批必做）：回写 backlog（销项/注记）与受影响验收册；中文提交信息 + 推送；提交前 secret 扫描覆盖本会话接触的全部敏感值（不只预设清单）。
4. 纪律：验收判据不满足就登记，不放宽；测试必须全绿再报完成（证据留档 runs/ 或提交说明）。

## 批1 — 测试基建：耗时治理 + 间歇失败稳定化

**对应 backlog**：P2 #10（终端界面测试 ~89 秒）、P2 #8（wsarecv 间歇失败原例）。
**为什么排第一**：#10 是测试自助化扩展的已定前置（「先治再扩」——不治它，批4 每加一条测试都更慢）；#8 同主题顺手收；两件都零 owner 门，新会话当天可开工。

**范围**：
- **#10 耗时治理**（`internal/tui`，现状 89.6 秒：editpage ~71s + 向导回环 ~7s + 端到端 ~7s）。已知事实（勿重复探路）：瓶颈 = 测试辅助函数同步执行 huh 表单光标闪烁的 530 毫秒定时闭包，睡满才丢弃；「BlinkSpeed 测试缝」已证不可行（cursor.Model 是 huh 内部逐字段实例，构造器不暴露）。已定方向：① `press()` 对普通字符键免等待（字段聚焦态字符键只产生闪烁重臂命令，无输出可等）；② 睡眠主导的测试加 `t.Parallel()`。
- **#8 间歇失败**：`internal/sshbroker` 的 TestConnectCancelContext 在 Windows 偶发 wsarecv 竞态（本地历史一次，持续集成连绿）。修法 = 重试式稳定化；同族 mcpserver 侧三例已用「固定轮询改期限轮询」修过（branch `flake8-deadline-polling`），姿势可参考。

**完成判据**：
- `go test ./internal/tui/` 计时前后对比留档（目标 < 30 秒；达不到如实登记实际值与原因）；
- 修改过的测试 `-count=10` 零失败；全仓 `go test ./...` 绿；
- 持续集成两平台绿后销项 backlog #10（#8 视修复形态销项或注记）。

**注意**：本批不改生产行为，纯测试面；不要顺手做批4 的扩展（纪律：先治后扩）。
