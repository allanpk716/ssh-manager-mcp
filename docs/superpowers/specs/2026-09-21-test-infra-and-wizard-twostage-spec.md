# 夜链首批实施规格:测试基建治理 + 配对向导两级条件表单(2026-09-21)

> 来源:剩余工作分批计划 rev1(2026-09-21 夜链评审收敛稿)× 评审决策快照 D1–D9;评审链记录在 `.xcheck/`(不入库)。
> 需求源:`docs/backlog.md` 活跃面第 2 条(#8/#10)、第 4 条、第 5 条 + 验收册 plan-46-45「待测试代证」层。
> 术语:主机公钥指纹、服务器公钥指纹指纹校验等见 `CONTEXT.md`;界面 = 终端界面(tui);配对向导 = `sshmgr pair` 的交互式入网向导。

## Problem Statement(用户视角)

1. 终端界面测试套件一次要跑约 89.6 秒,其中绝大部分是测试辅助函数在同步等待表单光标闪烁的 530 毫秒定时闭包——纯等待,不是计算。测试自助化主轴已定「先治再扩」,不治它,每加一条行为契约测试都更慢。
2. SSH 代理连接包里「取消上下文应中止在飞连接」这条测试在 Windows 上偶发竞态失败(历史本地一次,重跑即绿;持续集成连绿),削弱本地全量跑的可信度。
3. 配对向导现在把信任模式、服务地址、服务器公钥指纹放在同一张表单里:走局域网发现的新设备根本不需要填地址和指纹,却被三个字段一起打扰;走手动直连的设备又容易漏填指纹。owner 已拍板方案 B:两级条件表单。
4. 实例选择器的行状态四要素与非向导的 Esc 键链行为,验收册标注「待测试代证」——目前没有进程内测试钉住,界面改动可能悄悄破坏已验收行为。
5. doctor 探活二期的待审规格定稿于二进制改名之前,冻结文案里的旧二进制名与现行名不一致——owner 审阅前应完成更名适配,审的即是终稿。

## Solution(用户视角)

按分批计划的可无人值守部分一次夜链实施:先治理终端界面测试墙钟并稳定化偶发失败测试(批1);再把配对向导改成两级条件表单并以行为契约测试钉住其回环与 Esc 中止契约(批5);随后为实例选择器与非向导 Esc 键链补行为契约测试(批4 收窄版);顺手完成待审规格的更名适配(批3 前置小件);最后回写登记(判据不放宽:持续集成未验证的不销项,只登记)。

## User Stories

1. 作为本仓开发者,我想要终端界面测试套件的墙钟降到 30 秒以内,以便行为契约测试的扩展不被纯等待时间拖垮。
2. 作为本仓开发者,我想要「取消上下文应中止在飞连接」这条测试在 Windows 上不再偶发竞态失败,以便本地全量跑一次就有可信结论。
3. 作为给新设备配对的 owner,我想要配对向导先只问信任模式(局域网发现 / 手动直连),选了手动直连才出现服务地址与服务器公钥指纹两个字段(指纹必填并带来源提示),以便发现场景不被无关字段打扰、直连场景不漏填。
4. 作为配对中途反悔的用户,我想要在两级表单的任一级按 Esc 都立即纯返回原页面且零残留,以便中止路径行为一致、可预期。
5. 作为维护者,我想要实例选择器的行状态四要素与非向导 Esc 键链有进程内契约测试钉住,以便界面改动不悄悄破坏已验收行为。
6. 作为待审规格的审阅者(owner),我想要 doctor 探活二期待审稿里的命令示例与现行二进制名一致,以便审的即终稿。

## Implementation Decisions

- **测试耗时治理(批1 #10,方向已定不得另辟蹊径)**:① 字符键入测试辅助函数对普通字符键免等待——字段聚焦态下普通字符键只会产生光标闪烁重臂命令,无输出可等,不必同步执行;② 睡眠主导的既有测试加并行标记。「闪烁速度测试缝」已证不可行(界面库的闪烁定时器是内部逐字段实例,构造器不暴露),不采用。**纯测试面改动:终端界面包的生产文件零改动,生产行为零变化**(生产命令在运行时 goroutine 执行,不受测试等待方式影响)。
- **偶发失败稳定化(批1 #8)**:重试式/期限轮询式稳定化——同族先例 = 把固定轮询次数改成带截止时间的轮询,游标推进保证多轮零重复收集。被测契约本身不变(断言仍是「取消的上下文必须中止在飞连接」),只改等待方式。
- **两级条件表单(批5,方案 B)**:一级表单只问信任模式(局域网发现 / 手动直连);选「手动直连」才串联二级表单——服务地址 + 服务器公钥指纹两个字段,指纹必填并带指纹来源提示;选「局域网发现」则两个字段根本不出现(不是隐藏空值)。表单库无字段级显隐能力 → 拆两级表单串联实现;失败路径**重建**表单而非复用实例(沿用既有死锁教训纪律)。
- **Esc 中止契约(评审 D9 裁定)**:沿用现行向导既定语义「任意向导步骤 Esc = 纯返回页面、零残留」;两级形态下任一级 Esc 均为同一中止契约,不自创新行为。若实现中发现该语义无法直接映射两级形态,登记待决留 owner 裁决,不由实施者临时发明。
- **向导回环契约测试的唯一归属(评审 D9 裁定)**:配对向导回环的行为契约测试钉**两级表单形态**(含失败路径重建),与向导改造同票落地、先钉契约再实现(TDD 顺序);实例选择器与非向导 Esc 键链的契约测试独立成票,不碰向导面。
- **待审规格更名适配(批3 前置小件)**:仅把冻结文案里的旧二进制名(`ssh-manager` 形态的命令引用)换成现行名(`sshmgr`),不改任何技术内容、决策与结构;更早的修订链历史文件不动。
- **写作规范**:一切产出(代码注释、提交信息、文档)遵守 owner 2026-09-09 写作规范——禁非常见缩写与生僻词,名称自含可懂(CONTEXT.md 定义的领域词除外)。

## Testing Decisions

- **行为不回归是底线**:测试辅助函数改造后,既有全部测试的行为断言不变、必须全绿(改的是等待方式,不是断言)。
- **计时留档**:治理前后终端界面包测试计时对比留档;目标 < 30 秒,达不到如实登记实际值与原因,不放宽(批4 的「不回涨」基线 = 批1 完成时留档的实际计时值)。
- **稳定化验证**:修改过的测试 `-count=10` 零失败;全仓 `go test ./...` 绿。
- **两级表单契约测试**:至少钉住——选「局域网发现」→ 地址与指纹两字段不出现;选「手动直连」→ 两字段出现且指纹必填;失败路径表单重建(非复用);任一级 Esc = 纯返回页面零残留。
- **选择器与 Esc 链契约测试**:行状态四要素 + 非向导 Esc 链(列表过滤清除、覆盖层收起、确认取消等既有行为)的进程内测试;只加测试,生产文件零改动(若确需测试缝,回报待决不自行开缝)。
- **持续集成边界如实**:本仓持续集成只在 master 推送与拉取请求时触发,夜链分支不触发——backlog #10 的销项条件(两平台绿)只能在其后兑现;本夜只做本地全绿 + 登记,不提前销项。
- 竞态检测(-race)仅持续集成跑(本机 Windows 运行时损坏),本地验证以普通 `go test` 为准——与仓库既有实践一致。
