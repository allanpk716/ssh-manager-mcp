# 整体发版真机验收册（#87）

## 替代旧册声明

本册替代已废弃的原终端图形界面验收册
[plan-46-45-tui-flows.md](./plan-46-45-tui-flows.md)。旧册的废弃标注与正文是
历史记录，保持原样，不得为本册改写；其命令行等价面已跑的历史结论继续有效。
本册承接原终端图形界面删除后的图形界面验收，并按票 #87 汇总本次整体发版的
真机验收。

  与架构决策记录。后续条目引用具体依据时必须写在条目内。

## 取证模板

- 命令原文与完整输出必须成对留存；失败输出也原样留存，不修饰、不截断。
- 机密值、真实 IP 地址、主机名、账号名不得进入本册与运行记录。
- 涉及完整性断言时，附原文件与对照文件的 SHA-256 哈希值，并写明哈希算法。
- 远端操作必须注明经哪台代称机器执行；只用代称，不写真实网络标识。
- 浏览器取证留存页面文本、相关响应头或截图；截图前必须确认没有机密值、
  真实网络标识与账号名。

取证块使用以下格式：

```text
【命令原文】
<逐字保存命令>
【完整输出】
<逐字保存完整输出；失败同样保留>
【完整性对照】
<需要时写原文件、对照文件与两者的 SHA-256 哈希值>
【执行位置】
<写本机或经哪台代称机器执行>
```

### 证书指纹人工比对（#271 填写）

#### 人工271-1 主机密钥或主机证书指纹人工比对

标注：操作面=owner 命令行；证据来源=真机端到端
前置数据：
- 依据 #45、#67 与 ADR 0011，准备一台一次性靶机和一个一次性服务器条目；
  owner 先在靶机本体控制台、虚拟化控制台或供应商页面取得主机密钥指纹。若
  执行现场提供的是 SSH 主机证书指纹，则以同一外部事实来源记录该证书指纹。
- 指纹的事实来源、取得时间和取得路径由 owner 私下记录；本册和运行记录只写
  来源类别，不写真实地址、账号或凭据。
- agent 可以准备靶机和命令，但不得代替 owner 判断两个指纹是否相同。
执行步骤：
1. owner 触发一次性条目的首次连接，让自动首次信任生成锚。
2. owner 在持有 vault 的机器执行 `sshmgr servers pin-hostkey <一次性条目>`，
   读取 `fingerprint`、`source`、`handshake` 与 `created` 字段。
3. owner 把输出中的 SHA-256 主机密钥指纹（或主机证书指纹）与第 1 步之前
   取得的带外事实逐字人工比对。
4. 比对一致时保留该锚供后续锚定转发验收使用；不一致时立即停止后续信任
   验收，执行 `sshmgr servers pin-hostkey <一次性条目> --clear` 清理错误锚，
   并把不一致作为失败证据登记。
期望结果：
- owner 记录「人工比对一致」或「人工比对不一致」；一致时 `source` 能说明
  锚的来源，`handshake` 与真实握手所用地址相符，但真实地址不出现在证据里。
- 不一致时错误锚被清除，后续条目不会继续使用这把锚。
证据留存方式：
- 留存 owner 命令原文、把真实地址替换为代称后的完整输出、人工比对结论、
  指纹事实来源类别和取得时间；需要清理时留存清理命令与完整输出。
是否允许自动化替代：
- 不允许。自动化测试只能证明显示值与存储值一致，不能替代「外部事实来源
  与呈现指纹是否相同」的人工安全判断。

### Windows 桌面手动添加引导目验（#272 填写）

#### 人工272-1 Windows 桌面手动添加引导与盘符可见性目验

标注：操作面=浏览器；证据来源=真机端到端
前置数据：
- 依据 #42、规格 #238 与 ADR 0008，在公司 A 的权威端登记一处只供验收
  使用的一次性 SMB 共享存储；共享密码使用专用的一次性挂载账号，并只授权
  这处共享。真实地址、账号名与密码只存在 vault 和 owner 的密码管理器里。
- 家 A Windows 新版客户端（工作机 1）的桌面会话尚未手动映射这处共享；
  owner 先确认资源管理器里看不到本条目使用的固定盘符。
执行步骤：
1. owner 在权威端 `/ui` 打开「共享存储」列表，进入这处共享的详情页，再
  点击「打开桌面手动添加引导」。
2. 在「这台电脑是拓扑里哪台设备」中选择工作机 1 对应的设备，点击
  「显示引导」。
3. 目验推荐地址、所属网络、固定盘符、访问路径、目录约定访问路径、
  Windows 手动映射步骤和等价命令
  `net use <盘符>: \\<地址>\<共享名> /user:<账号> * /persistent:yes`；
  确认页面写明命令里的 `*` 表示运行时输入密码。
4. 目验页面的「注意事项」：笔记本更换网络后映射可能失效；页面不显示、
  复制或下载共享密码，也不生成含密码的脚本，只提示 owner 输入自己保存
  在密码管理器里的密码。
5. owner 按页面步骤在工作机 1 的桌面会话手动映射盘符，输入自己保存的
  共享密码，写入并读取一个小文件；随后断开这个手动映射。
期望结果：
- 地址推算优先显示工作机 1 与提供方设备共同所在的物理局域网；页面步骤
  与登记的盘符、共享名、目录约定一致。
- 页面没有密码输入框、显示密码、复制密码或下载脚本入口，页面文本和
  截图中不出现共享密码。
- 手动映射前桌面看不到 sshmgr 在受管 Windows 服务器命令会话里注入的
  盘符；手动映射后桌面能访问共享；断开后不再留这个盘符。
证据留存方式：
- 留存脱敏后的页面文本或截图、owner 的目验结论、手动映射读写结论和
  断开清理结论；真实地址、账号名、密码与文件内容不得进入证据。
是否允许自动化替代：
- 不允许。桌面可见性、引导步骤是否足够清楚以及页面上没有密码入口，
  都是 owner 的人工视觉与安全判断；自动化测试只能代证页面字段契约。

### 1.2 网络拓扑与主机信任（#271 填写）

#### 单机271-1 站点、网络、设备与网络成员登记和删除预览

标注：操作面=owner 命令行；证据来源=真机端到端
前置数据：
- 依据 #35、#50、#67、规格 #122 与 ADR 0011，在家 A 的单机演练机的一次性
  演练 vault 中准备：一个一次性站点、一个物理局域网、一个虚拟局域网、
  一台代表本机的一次性设备、一台一次性受管靶机设备，以及靶机的一条一次性
  服务器条目。所有名字都带一次性标记，真实地址只写入 vault。
- 靶机设备登记物理局域网地址与虚拟局域网地址；本机设备也登记为这两个网络
  的成员。
执行步骤：
1. 依次执行 `sshmgr sites add`、`sshmgr networks add --type physical`、
   `sshmgr networks add --type virtual`、`sshmgr devices add`、
   `sshmgr devices member add` 与 `sshmgr servers add --device`，创建
   一次性拓扑和服务器条目。
2. 用 `sshmgr sites list`、`sshmgr networks list`、`sshmgr devices list` 与
   `sshmgr devices show` 核对站点、网络属性、设备、多个网络成员与服务器
   条目的呈现。
3. 分别用 `sites edit`、`networks edit`、`devices edit` 与
   `devices member edit` 修改名字、备注、网段、标称带宽、是否按流量计费
   和地址；再执行一次 `networks edit --type`，确认网络类型不可修改。
4. 交互式执行 `sshmgr networks rm <一次性网络>`，确认删除前输出该网络的
   全部网络成员清单；删除最后一个网络后核对「候选地址只剩兜底 Host」的
   逐条提示。
5. 交互式执行 `sshmgr devices rm <一次性靶机设备>`，确认预览包含服务器
   条目与锚、共享存储、机密项可写入服务器列表、下发记录、网络成员、布局
   坐标、软件清单计数和客户端实例关联，然后只输入一次 `y` 确认。
6. 网络清空后执行 `sshmgr sites rm <一次性站点>`；再核对一次性服务器条目、
   设备、网络与站点均无残留，并核对审计和清理输出。
期望结果：
- 物理局域网必须归属站点、虚拟局域网不能归属站点、同一网络内地址重复被
  拒绝；不同网络的网段重复不被拦截。

#### 单机271-2 同设备多个服务器条目与真实选址

标注：操作面=owner 命令行；证据来源=真机端到端
前置数据：
- 依据 #35、#36、#45、#50、#67 与 ADR 0011，在家 A 的单机演练机上保留
  单机271-1的一次性物理局域网与虚拟局域网；一次性靶机设备登记两个网络的
  地址，本机设备也登记在两个网络里。
- 创建两个一次性服务器条目：条目 A 先关联一次性靶机设备；条目 B 先留在
  自动生成的未归类设备上，稍后移入同一设备。两者可以使用不同用户、端口
  和一次性凭据。
- 执行 `sshmgr devices local set <本机一次性设备>`，让单机部署知道实际拨号
  设备是哪台。
执行步骤：
1. 执行 `sshmgr ssh <条目A> <只读命令>`，让条目 A 首次锚定。
2. 执行 `sshmgr devices move-server <条目B> --to <一次性靶机设备>`；同端口
   兄弟条目应复制条目 A 的锚，并写 `pin-copy` 审计。
3. 用 `sshmgr devices show <一次性靶机设备>` 核对两个服务器条目都在同一

   `sshmgr ssh <条目B> <只读命令>`，核对条目 B 也可按共同网络成员地址连接。
4. 在本机 vault 的命令行执行 `sshmgr servers pin-hostkey --list`，核对两个
   条目各有一把锚；随后执行 `sshmgr servers pin-hostkey <条目A> --clear`，
   再显示条目 A 与条目 B 的锚，核对清除只影响条目 A。
5. 把本机设备移出一次性物理局域网后重试条目 A，核对连接改走虚拟局域网
   地址；再把本机设备移出全部共同网络，并让该条目的兜底主机不可达，核对
   失败提示要求补登记本机设备与目标设备的共同网络。
6. 验收结束后清除本机设备设定，并删除两个一次性服务器条目、靶机设备、
   网络与站点。
期望结果：

- 同在物理局域网时先走物理局域网地址；失去物理共同网络后走虚拟局域网地址；
  无共同网络时只尝试兜底主机，失败提示补登记，不盲试目标全部地址。

#### 权威端272-2 撤销、残留检查与换密码说明

标注：操作面=owner 命令行；证据来源=真机端到端
前置数据：
- 依据 #32、#42、规格 #212 与 ADR 0008，在公司 A 的权威端准备一个
  一次性共享和专用一次性挂载账号；使用三条一次性服务器条目：Linux 靶子、
  macOS 靶子和 Windows 靶子。三条条目都在挂载密码机密项的可写入服务器
  列表内。破坏性清理只允许作用于这些一次性靶子。
- Linux 与 macOS 靶子已由 `shares mount` 挂载；Windows 靶子已通过一次
  命令会话验证盘符可注入。owner 私下准备第二个人工输入的新共享密码。
执行步骤：
1. owner 用标准输入传入新的共享密码，执行
   `sshmgr shares revoke <一次性共享名> <一次性macOS条目> --unmount --new-password-stdin --yes`，
   保存输出中的换密码提醒与真正的撤销手段说明。
2. owner 在 macOS 靶机上核对 autofs 映射条目已删除、挂载已卸载、只留撤销
  标记；再执行 `sshmgr shares residue <一次性共享名>` 核对结论。
3. owner 执行
   `sshmgr shares revoke <一次性共享名> <一次性Linux条目> --unmount --yes`，
   保存版本号、远端清理结果与审计。
4. owner 在 Linux 靶机上核对 `/etc/fstab` 管理行和凭据文件已删除、挂载
  已卸载、只留下不含密码与地址的撤销标记；执行
   `sshmgr shares residue <一次性共享名>`，核对该靶子报告「仅有撤销标记」。
5. owner 执行
   `sshmgr shares revoke <一次性共享名> <一次性Windows条目> --yes`，
   核对命令不连接 Windows 服务器，并输出「各客户端同步快照后停止注入」、
   长期离线客户端的例外，以及「真正的撤销手段是更换共享密码」的说明。
6. 在新版客户端同步新快照后，agent 对 Windows 靶子执行一条引用固定盘符
   的命令；再等待超过快照保鲜周期后重复一次，核对两次都不再注入该共享。
7. owner 依次用 `shares unmount` 清理 Linux 与 macOS 靶子上的撤销标记，
   执行 `shares residue` 复查，再删除一次性共享、机密项、三条服务器条目
   与相关拓扑登记；保留全部清理输出。
期望结果：
- Linux 与 macOS 都是先删除持久配置、再写撤销标记、最后卸载；卸载成功后
  不会自动挂回，撤销标记只含编码共享名、版本号与撤销状态。
- 残留检查把 Linux 与 macOS 报为「仅有撤销标记」，把 Windows 服务器跳过
  并说明其上没有 sshmgr 持久配置；不可达靶子不会被排队成待清理清单。
- 换密码输出列出仍可挂载的 Linux 与 macOS 服务器，提醒它们要按新版本号
  重新挂载，也提醒桌面手动连接需要换密码；新密码不进入命令参数或证据。
- Windows 撤销只改登记，在线客户端同步后停止注入；输出如实说明长期离线
  客户端仍会继续注入，真正撤销靠更换共享密码。
证据留存方式：
- 留存每条命令原文与完整输出、Linux 与 macOS 靶机的配置删除证据、撤销
  标记的安全字段结论、残留检查输出、Windows 注入停止证据、审计查询
  `share-revoke`、`share-revoke-remote`、`share-unmount`、
  `share-residue-check` 与清理输出；不得保存新旧密码或真实地址账号。
是否允许自动化替代：
- 不允许。撤销是破坏性动作，必须在一次性真机靶子上验证实际配置删除、
  撤销标记、快照同步边界与清理结果；自动化测试不能替代这些证据。

  密码不得进入证据。
是否允许自动化替代：
- 不允许。重选会卸载并重挂真实挂载，属于破坏性动作，必须在一次性靶机
  上实证；并发与负路径契约另由单机272-4自动化测试代证。

### 3.2 网络拓扑与主机信任（#271 填写）

#### 客户端271-1 客户端拓扑查询、连通探测与本地结果边界

标注：操作面=agent 工具面；证据来源=真机端到端
前置数据：
- 依据 #35、#36、#44、#67、规格 #128、规格 #142 与规格 #234，公司 A 的
  权威端已登记公司 A 权威端设备、家 A Windows 新版客户端（工作机 1）设备、
  Linux 受管服务器 A 与 NAS A；客户端设备与目标设备的共同网络、无共同网络
  目标和未登记服务器都存在。
- 新客户端的一次性命名实例用一次性设备码绑定访问配置组并执行
  `sshmgr cache pull`；快照按授权范围裁剪拓扑，客户端实例自己的设备随
  快照下发。
执行步骤：
1. 在客户端调用 `query_topology`，参数 `from="self"` 且不传 `to`，核对分组
   视图；再分别调用带 `to` 的默认档和 `detail=true` 展开档。
2. 在客户端调用 `probe_connectivity`，参数 `from="self"`、`targets` 包含
   `NAS A:445`；再以 Linux 受管服务器 A 的编号为 `from`，探测它到
   `NAS A:445`。
3. 调用后立即再次执行 `query_topology from="self"`，核对最近探测结果和
   相对观察时间出现在对应网络行。
4. 查看客户端实例目录的 `cache-audit.log` 与 `probe-results.json` 摘要；
   再到权威端查询自身 `query_topology from="self"` 的同名目标，确认没有
   出现客户端本机刚写入的观察。
5. 在客户端执行 `sshmgr sites add <一次性站点>`，确认写命令被拒绝并提示
   到权威端执行。
6. 验收结束后删除一次性命名实例目录，并在权威端删除一次性拓扑登记与
   服务器条目。
期望结果：
- 客户端查询只读本地裁剪快照和本实例探测结果；授权范围外的服务器不出现在
  任何分组，包括不可达与未登记分组。
- 默认输出紧凑分组；`detail=true` 只在服务器条目允许显示主机时展开地址，
  不受管设备地址始终显示为隐藏，输出不含网段。
- 两次探测都写客户端实例本地审计 `probe-connectivity`；观察带时间，只存在
  客户端本地 `probe-results.json`，不回传权威端。
- 客户端拓扑写命令被拒绝，查看命令可读缓存。
证据留存方式：
- 留存工具调用原文与完整输出、客户端本地审计摘要、本地探测结果摘要、
  权威端对照查询输出、写命令拒绝输出和清理输出；真实地址必须打码。
是否允许自动化替代：
- 不允许用自动化测试替代。客户端快照、客户端本地审计、权威端对照和本地探测结果
  文件的边界必须在新版 Windows 客户端真机上成立。

#### 客户端271-2 多地址试连与主机密钥不一致跳过

标注：操作面=agent 工具面；证据来源=真机端到端
前置数据：
- 依据 #36、#44、#45、#67、规格 #132 与 ADR 0011，在新客户端可见的一次性
  目标设备上登记三个候选：物理局域网的第一地址指向一台呈现不同主机密钥的
  一次性靶机，虚拟局域网地址指向真正目标，服务器条目的兜底主机最后。
- 真正目标条目已锚定到正确主机密钥；错误靶机与真正目标使用相同端口，且
  agent 可经 SSH 工具面读取错误靶机的 SSH 服务日志。客户端已拉取包含该
  拓扑的快照。
执行步骤：
1. 调用 `exec_command`，在该一次性服务器条目上执行一个只读命令。
2. 读取返回结构中的 `connection_notes`，核对错误物理地址被说明为呈现不同
   主机密钥并已跳过。
3. 经 SSH 工具面查看错误靶机的 SSH 服务日志，核对该连接在认证请求前关闭，
   没有收到登录凭据。
4. 读取客户端本机 `probe-results.json` 的摘要，按观察时间整理实际尝试顺序；
   运行记录只写「物理局域网第 1 地址、虚拟局域网第 1 地址」这样的实际顺序，
   并另行记录规划中的兜底主机排在最后，不写真实地址。
5. 用 `query_topology from="self"` 查看该目标，确认查询只给登记分组和最近
   观察，不把被跳过地址伪装成连通。
6. 删除两个一次性靶机、服务器条目与拓扑登记；客户端缓存与本地探测结果
   随一次性命名实例目录一起删除。
期望结果：
- 命令最终经真正目标地址成功执行；返回中的连接说明只用网络名和序号指称
  被跳过地址。
- 错误靶机没有认证请求；被跳过地址不进入成功地址缓存，也不改写为成功观察。
- 本地探测结果能证明实际尝试顺序为物理局域网错误地址在前、可用地址在后。
证据留存方式：
- 留存工具调用原文与完整返回、错误靶机认证日志摘要、本地探测结果的网络名
  与顺序摘要、清理输出；真实地址、账号与凭据不得进入证据。
是否允许自动化替代：
- 不允许用自动化测试替代。真实客户端、错误靶机与正确靶机的网络路径和
  认证日志是本条判据；更细的函数级顺序断言由单机271-3代证。

#### 客户端271-3 首次锚定仅走虚拟局域网并转发

标注：操作面=agent 工具面；证据来源=真机端到端
前置数据：
- 依据 #45、#50、#67、规格 #132 与 ADR 0011，权威端有一个未锚定的一次性
  条目，其设备同时登记物理局域网地址与虚拟局域网地址；新客户端的一次性
  命名实例两个地址都可达，且已拉取快照。
- 人工271-1的带外指纹事实已由 owner 准备好；权威端审计和服务日志可查询。
执行步骤：
1. agent 在新客户端调用 `exec_command`，对该未锚定条目执行只读命令。
2. 读取客户端本机 `probe-results.json` 摘要，核对本次只出现虚拟局域网候选
   的握手观察，没有物理局域网候选的认证尝试。
3. owner 按人工271-1比对权威端落库指纹；agent 留存权威端 `pin-forward`
   审计摘要，不代替人工判断。
4. 在同一客户端重复调用一次 `exec_command`，核对已有锚不会被转发请求覆盖，
   第二次连接可以按正常选址规则使用物理局域网地址。
5. 删除一次性服务器条目与设备拓扑登记；客户端缓存与本地探测结果随一次性
   命名实例目录一起删除。
期望结果：
- 首次连接只经虚拟局域网地址完成首次信任，并把真实握手地址随锚定转发提交
  权威端；物理地址不会在无锚状态下先被信任。
- 权威端仅新增锚，不覆盖已有锚；第二次连接物理局域网地址与虚拟局域网地址
  共用同一把锚。
证据留存方式：
- 留存两次工具调用与完整输出、客户端本地观察摘要、把真实地址替换为代称的
  权威端锚显示与 `pin-forward` 审计、owner 人工比对结论和清理输出；真实
  地址必须打码。
是否允许自动化替代：
- 不允许用自动化测试替代。真实客户端握手、权威端落库和第二次真实连接是
  本条判据；非法握手地址分支由权威端271-2的自动化测试代证。

### 3.3 共享存储（#272 填写）

#### 客户端272-1 快照裁剪、名单查询与幂等挂载

标注：操作面=agent 工具面；证据来源=真机端到端
前置数据：
- 依据 #32、#37、规格 #191、#198 与 ADR 0008、0009，家 A Windows 新版
  客户端（工作机 1）使用一次性实例和一次性设备码连接公司 A 的权威端。
- 权威端准备两处一次性共享：共享 A 的挂载密码机密项可写入客户端可见的
  Linux 条目；共享 B 的机密项只可写入该客户端不可见的服务器。客户端
  profile 只授予 Linux 条目与后续 Windows 条目，不授予共享 B 的任何
  可挂载服务器。
执行步骤：
1. agent 在一次性客户端实例执行 `sshmgr cache pull`，调用 `list_shares`，
   核对只能看到共享 A，看不到共享 B；共享 A 的 `servers` 只带 Linux 条目
   与约定挂载点。
2. agent 调用 `mount_share`，参数 `share=<共享A>`、
   `server_id=<Linux条目标识符>`，记录首次结果、版本号、网络名、地址
   序号与目录约定路径。
3. agent 重复同样调用，核对 `result="no-change"`、配置不被改写。
4. owner 在权威端修改共享 A 的提供方设备网络成员地址；等待客户端保鲜
   或执行 `sshmgr cache pull` 后，agent 再调用任意 sshmgr 工具，保存开头
   的变更提示，并调用 `list_shares` 核对版本号加一。
5. agent 调用 `list_shares`，参数 `live_check=true`、
   `check_server=<Linux条目标识符>`，核对现场状态为 `mounted`，结果不含
   地址、账号或密码。
6. 清理时由 owner 撤销并卸载一次性 Linux 靶子，删除一次性客户端实例
  缓存与设备码，再删除权威端两处共享与相关登记；保留清理输出。
期望结果：
- 客户端快照按 profile 与可写入服务器列表交集裁剪：共享 A 可见，共享 B
  完全不可见；输出不泄露共享 B 的共享名、提供方设备或机密项引用。
- `mount_share` 在客户端先做快照保鲜，再执行幂等挂载；版本变化后变更
  提示只出现一次，并指出可能需要更新的服务器。
- 现场检测只读、不写审计；挂载状态与远端配置版本能安全呈现。
证据留存方式：
- 留存客户端命令与 MCP 工具调用原文及完整输出、两次挂载结果、变更提示、
  现场检测输出、清理输出；真实地址与账号必须打码。
是否允许自动化替代：
- 不允许。真实权威端快照下发、客户端裁剪、快照保鲜与远端挂载必须真机
  实证；字节级快照裁剪契约另由单机272-4自动化测试代证。

#### 客户端272-2 Windows PowerShell 与 cmd 会话内网络盘符注入

标注：操作面=agent 工具面；证据来源=真机端到端
前置数据：
- 依据 #42、规格 #205、票 #206 与 #288、ADR 0008，工作机 1 的一次性
  客户端实例可访问 Windows 受管服务器 A 的 PowerShell 服务器条目与 cmd
  服务器条目；一处一次性共享的固定盘符对两条条目都适用，挂载密码机密项
  的可写入服务器列表包含这两条条目。
- owner 确认两个服务器条目的默认 shell 分别是 PowerShell 与 cmd；NAS A
  已关闭「禁止同一 IP 多个连接」类限制。为认证失败演练准备一次性专用
  挂载账号，避免影响生产账号。
执行步骤：
1. agent 分别对两条 Windows 条目调用 `exec_context`，核对
   `planned_network_drives` 列出共享名与 owner 登记的固定盘符，
   `uninjected_network_drives` 为空。
2. agent 对 PowerShell 条目调用 `exec_command`，执行
   `Get-ChildItem <盘符>:\<子路径>`；对 cmd 条目执行
   `dir <盘符>:\<子路径>`。记录 `injected_network_drives`、用户命令输出
   与追加的映射警告。
3. 在同一命令中分别读取当前进程命令行：PowerShell 条目执行
   `$process = Get-CimInstance Win32_Process -Filter "ProcessId=$PID"; $process.CommandLine`；
   cmd 条目执行
   `powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter 'name=''cmd.exe''' | Select-Object ProcessId,CommandLine"`。
4. owner 暂时把一次性挂载密码换成错误值；agent 同步客户端快照后，对
   PowerShell 条目连续调用两次 `exec_command` 执行只读命令，保存第一次
   认证失败警告与第二次「共享因认证失败已暂停注入」输出。
5. owner 把正确密码写回机密项；agent 同步新版本号后再调用一次命令，核对
   暂停自动解除、盘符重新注入且命令不被映射失败阻断。
6. 查询客户端本地 `cache-audit.log`，确认命令文本只含 agent 原命令，
   审计只记录注入共享名，不含地址、账号或密码。
7. 清理时撤销授权、同步客户端、删除两条一次性服务器条目与一次性共享、
  机密项和测试账号登记；保留清理输出。
期望结果：
- PowerShell 与 cmd 的每条命令都在同一个 SSH 登录会话内先由
  `WNetAddConnection2` 映射 owner 指定的固定盘符，用户命令能列出共享内容；
   `injected_network_drives` 只含共享名与盘符。
- 映射封装的内部状态行不出现在输出中；密码只经标准输入送达，不出现在
  远端命令文本、目标机进程命令行、工具返回、任务日志或审计里。
- 认证失败输出「共享密码认证失败，已暂停注入，请同步或检查机密项」；
  下一次命令不再尝试该共享，其他命令继续执行；共享存储版本号变化后暂停
  自动解除。
- 盘符只在当前命令会话内可见；本条目不把它当作桌面、Windows 服务或
  计划任务的可见性证明，桌面目验由人工272-1负责。
证据留存方式：
- 留存两个 shell 的工具调用原文、结构化返回、进程命令行检查、两次暂停
  输出、恢复输出、本地 `cache-audit.log` 相关行和清理输出；真实地址、
  账号、密码与共享内容必须打码。
是否允许自动化替代：
- 不允许。真实 Windows OpenSSH 会话、两种默认 shell、目标机进程命令行
  和认证失败暂停必须真机实证；注入拼装与警告分类另由单机272-4自动化
  测试代证。

#### 客户端272-3 共享地址中继本地拷贝、流式回退与重跑

标注：操作面=agent 工具面；证据来源=真机端到端
前置数据：
- 依据 #54、规格 #235 与 ADR 0016，工作机 1 的一次性客户端实例可见一处
  一次性共享、两条一次性 Linux 条目和 Windows 受管服务器 A 的一次性条目。
  Linux 条目 A 与提供方设备同在物理局域网，Linux 条目 B 只与提供方设备
  同在虚拟局域网；两条 Linux 条目都已实际挂载共享，Windows 条目可挂载但
  无需持久挂载。
- 准备一个大于传输块大小的一次性源文件、一个普通服务器目标路径、一个
  执行实例本地源文件，以及共享内的一次性源路径与目标路径。所有路径只供
  验收使用，跑完清理。
执行步骤：
1. agent 调用 `query_topology`，参数 `from=<Linux条目标识符>`、
   `to=<一个共享地址>`，核对返回的服务器、共享存储、可挂载结论与实际
   路径；再执行一条 `exec_command`，确认命令文本中的共享地址不被改写。
2. agent 调用 `relay_file`，参数 `from_share_address=<共享地址>`、
   `to_server_id=<Linux条目A标识符>`、`to_path=<一次性目标路径>`；轮询
   `exec_output` 到终态，记录 `mode="local_copy"`、
   `restart_after_interruption=true`、任务输出中的固定 `cp` 命令和从头
   重跑提示。
3. 反向调用 `relay_file`，参数 `from_server_id=<Linux条目标识符>`、
   `from_path=<一次性普通路径>`、`to_share_address=<共享地址>`，核对规则
   对称、仍在 Linux 服务器本地拷贝，并在完成后删除半成品。
4. agent 调用 `relay_file`，参数 `from_share_address=<共享地址>`、
   `to_server_id=<Windows条目标识符>`、`to_path=<Windows盘符根下的目标路径>`，
   核对同一 SSH 命令会话内先用 `WNetAddConnection2` 映射固定盘符，再执行
   固定 `robocopy`；任务终态说明本地拷贝、半成品目录与从头重跑语义。
5. agent 以执行实例本地文件为源端、共享地址为目标端调用 `relay_file`，
   先不传 `via`，核对回退为 `mode="streaming_relay"`，
   `share_endpoint_server_id` 指向同在物理局域网的 Linux 条目 A；再用参数
   `via=<Linux条目B标识符>` 与新的一次性目标路径重跑一次，核对指定虚拟
   局域网端点覆盖自动选择。
6. agent 调用 `relay_file` 同时传 `from_share_address` 与
   `to_share_address`，保存完整报错「源端和目标端不能都是共享地址；请先
   用 query_topology 查询实际路径，再在可挂载共享的服务器上用
   exec_command 拷贝」。
7. 对第 2 步重新启动一次大文件本地拷贝，调用 `exec_stop(task_id)` 中途停止；
   确认目标端存在 `<目标>.sshmgr-partial` 且没有块清单；重跑同参数任务，
   核对输出说明从文件开头覆盖旧半成品，最终文件完整。
8. 在源端与目标端用 SHA-256 哈希工具比对最终文件；清理共享内文件、普通
   服务器文件、半成品、本地源文件与一次性登记，保留清理输出。
期望结果：
- 一端是共享地址且另一端可挂载时，`mode="local_copy"`；Linux 在已挂载
  服务器上执行固定 `cp`，Windows 在注入盘符的同一命令会话执行固定
  `robocopy`，文件字节不经执行实例内存。
- 另一端不可挂载时回退为流式中继；自动选择优先与提供方设备同在物理
  局域网且已实际挂载的 Linux 或 macOS 服务器，并列时按服务器名字升序；
   `via` 可以指定这样的端点，但不能用于已决定本地拷贝的普通服务器端。
- 两端都是共享地址直接报错；本地拷贝中断、停止或失败后不生成块清单、
  不能续传，重跑从文件开头覆盖旧半成品；完成后目标真名出现、半成品消失。
- 工具返回、任务输出与客户端本地 `cache-audit.log` 只有元数据，不含文件
  内容、共享密码、挂载账号或额外候选地址。
证据留存方式：
- 留存每次工具调用与任务轮询原文及完整输出、任务标识符、模式字段、
  端点服务器标识符、停止与重跑输出、源端与目标端 SHA-256 哈希、清理
  输出、本地 `cache-audit.log` 相关行；共享地址中的真实主机必须替换为
  代称，账号与密码不得进入证据。
是否允许自动化替代：
- 不允许。真实提供方设备、Linux、Windows 与执行实例之间的数据路径、`robocopy`
  行为、停止后重跑和哈希完整性必须真机实证；多候选排序与安全输出契约
  另由自动化测试补充。

### 4.2 网络拓扑与主机信任（#271 填写）

#### 混跑271-1 旧客户端、新权威端的兜底锚与旧格式转发拒绝

标注：操作面=owner 命令行；证据来源=真机端到端
前置数据：
- 依据 #45、#67、规格 #132 与 ADR 0011，工作机 1 上的旧版本第二实例使用
  一次性缓存目录和一次性设备码，仅授予两个一次性条目：条目 A 已按正确主机
  密钥锚定且兜底主机可达；条目 B 未锚定、兜底主机可达。
- 新权威端为条目 A 的快照推导旧格式兜底锚；两个条目的设备拓扑存在，但旧
  客户端版本不支持读取网络拓扑。
执行步骤：
1. 在旧版本第二实例执行 `sshmgr cache pull`，再执行
   `sshmgr ssh <条目A> <只读命令>`。
2. 在旧版本第二实例执行 `sshmgr ssh <条目B> <只读命令>`，触发旧格式首次
   锚定转发请求。
3. 查看新权威端 `serve` 服务日志中 `/pin-hostkey` 的状态行，并查询条目 B
   的锚与权威端审计。
4. 用源码测试补充旧格式请求契约：
   `go test ./internal/mcpserver -run '^TestPinHostkey_OldFormatRejected400$'`
5. 清理旧版本第二实例的一次性缓存、设备码、两个服务器条目和相关拓扑登记。
期望结果：
- 条目 A 照常只用兜底主机连接，导入的旧格式兜底锚校验通过；它得不到多地址
  选址能力，但也不能因新快照而失败。
- 条目 B 的旧格式转发请求缺少服务器条目标识，被新权威端以状态码 400 拒绝，
  并提示升级客户端；权威端没有为条目 B 落锚。
- 拒绝发生在发送登录凭据之前；服务日志和自动化测试均证明旧格式请求不会被
  猜测归属到某个条目。
证据留存方式：
- 留存旧客户端两条命令原文与完整输出、权威端服务日志状态行、条目锚显示、
  审计查询、自动化测试完整输出和清理输出；真实地址与账号必须打码。
是否允许自动化替代：
- 不允许用自动化测试替代。旧客户端二进制、新权威端推导的旧格式锚和真实
  兜底主机路径必须真机实证；请求形状契约可由第 4 步测试代证。

#### 混跑271-2 新客户端遇旧权威端的拓扑入口降级

标注：操作面=agent 工具面；证据来源=真机端到端
前置数据：
- 依据 #44、#67、规格 #234 与 ADR 0014，家 A Windows 新版客户端（工作机 1）
  的一次性实例指向不支持网络拓扑的旧权威端，并已完成一次缓存拉取；该缓存
  快照没有推荐版本字段。
- 旧权威端中仍有一个可执行命令的授权服务器条目，用于确认降级只影响网络
  拓扑入口。
执行步骤：
1. 在新客户端调用 `query_topology`，参数 `from="self"`。
2. 在新客户端调用 `probe_connectivity`，参数 `from="self"`、`targets` 包含
   一个已授权目标。
3. 在新客户端执行 `sshmgr sites list` 与 `sshmgr devices list`。
4. 对仍授权的普通服务器条目调用 `exec_command` 执行只读命令。
期望结果：
- `query_topology` 与 `probe_connectivity` 均返回固定错误「权威端版本过旧，
  不支持网络拓扑与共享存储，请先升级权威端」，不把版本混跑误报成拓扑缺失。
- 客户端拓扑查看命令同样拒绝；普通命令执行能力不因拓扑入口降级而失败。
证据留存方式：
- 留存四个调用或命令的原文与完整输出、客户端和权威端版本号、一次性实例
  清理输出；真实地址与账号必须打码。
是否允许自动化替代：
- 不允许用自动化测试替代。新旧二进制的实际缓存格式、工具注册面和错误呈现

#### 混跑272-1 旧客户端遇新权威端的无挂载与无盘符注入

标注：操作面=agent 工具面；证据来源=真机端到端
前置数据：
- 依据 #30、#51、规格 #240 与 ADR 0014，工作机 1 上的旧版本第二实例使用

- 旧版本实例不得连接生产条目；新权威端为它生成的一次性设备码与缓存

2. 经旧实例调用 `list_servers`，再用一次性 Windows 条目执行一条只读

3. 经旧实例在 PowerShell 条目执行
   `Get-ChildItem <固定盘符>:\<子路径>`，在 cmd 条目执行

4. 尝试在旧实例调用 `list_shares` 与 `mount_share`（若工具清单中存在才

- 旧实例工具清单没有新版的共享存储挂载工具；它看不到网络拓扑与共享存储
  名单，也不会因新权威端快照携带共享段而失败。
- 普通 SSH 命令仍可用，但命令前没有网络盘符注入，也没有映射警告；引用

证据留存方式：
- 留存旧客户端版本号、缓存拉取与工具枚举输出、三条命令原文及完整输出、
  清理输出；真实地址与账号必须打码。
是否允许自动化替代：
- 不允许。旧版本二进制与新权威端快照的实际兼容行为必须在版本混跑真机

#### 混跑272-2 新客户端遇旧权威端的共享入口降级

2. 调用 `query_topology`，参数 `from=<服务器条目标识符>`、
   `to=<一个共享地址>`。
3. 调用 `relay_file`，一端传共享地址、另一端传授权服务器常规路径。

  网络拓扑与共享存储，请先升级权威端」。
- `exec_context` 的网络盘符预览说明权威端过旧；`exec_command` 普通命令
  仍能执行，且不注入网络盘符。
- 客户端命令行共享查询与 `update` 出口都提示先升级权威端，不把版本混跑

证据留存方式：
- 留存新旧两端版本号、五类工具或命令调用原文及完整输出、一次性实例
  清理输出；真实地址与账号必须打码。
是否允许自动化替代：
- 不允许。新旧二进制、真实缓存格式和工具注册面的降级行为必须版本混跑
  真机实证；错误常量契约另由自动化测试代证。

## 既有 Windows 环境变量注入条目（#270 并入结构）

以下原文来自本册先前已开工内容，先原样保留；#270 把 W1、W2 与取证清理

## 前置条件

- sshmgr 已构建为包含机密项环境变量注入的版本。
- 准备一台临时 Windows 服务器，owner 分别用 PowerShell 与 cmd 两个服务器条目
  指向它；两个条目都使用一次性测试机密项，跑完删除测试数据。
- 测试机密项值至少包含中文、空格、引号、百分号、反斜杠与连字符，长度不小于
  32 个字节，且不含换行；owner 在验收记录中保留该测试值的事实来源，不把值
  写入本册或运行记录。

## W1 PowerShell 读帧【agent 可跑】

1. owner 创建机密项并设置环境变量名 `WIN_PS_TOKEN`，授权给 PowerShell 服务器
   条目。
2. agent 调用 `exec_command` 执行：
   `Write-Output $env:WIN_PS_TOKEN`
3. agent 再调用 `exec_command` 执行：
   `$process = Get-CimInstance Win32_Process -Filter "ProcessId=$PID"; $process.CommandLine`

**判据**：第 2 步输出只含 `{{sshmgr-secret:机密项名}}`，没有未注入警告；
第 3 步输出包含 PowerShell 进程命令行，但 owner 对照测试值确认命令行参数里
没有值，输出遮蔽名单也没有因命令行泄漏而出现机密项名。

## W2 cmd 读帧【agent 可跑】

1. owner 创建机密项并设置环境变量名 `WIN_CMD_TOKEN`，授权给 cmd 服务器条目。
2. agent 调用 `exec_command` 执行：
   `echo %WIN_CMD_TOKEN%`
3. agent 再调用 `exec_command` 执行：
   `powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter 'name=''cmd.exe''' | Select-Object ProcessId,CommandLine"`

**判据**：第 2 步输出只含 `{{sshmgr-secret:机密项名}}`，没有未注入警告；
第 3 步输出包含 cmd 进程命令行，但 owner 对照测试值确认命令行参数里没有值，
输出遮蔽名单也没有因命令行泄漏而出现机密项名。

## 取证与清理

- 每步保存工具调用的原始命令、返回结构化结果、`masked` 名单与审计查询输出；
  禁止把测试值写进验收证据。
- 验收结束后删除两个临时服务器条目、测试机密项与其授权；清理失败要原样
  记录，不得把失败留成无证据的完成项。
