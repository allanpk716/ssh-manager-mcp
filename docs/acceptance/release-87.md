## 替代旧册声明

本册替代已废弃的原终端图形界面验收册
[plan-46-45-tui-flows.md](./plan-46-45-tui-flows.md)。旧册的废弃标注与正文是

本册承接原终端图形界面删除后的图形界面验收，并按票 #87 汇总本次整体发版的
真机验收。

  与架构决策记录。后续条目引用具体依据时必须写在条目内。

## 取证模板

- 命令原文与完整输出必须成对留存；失败输出也原样留存，不修饰、不截断。
- 机密值、真实 IP 地址、主机名、账号名不得进入本册与运行记录。
- 涉及完整性断言时，附原文件与对照文件的 SHA-256 哈希值，并写明哈希算法。
- 远端操作必须注明经哪台代称机器执行；只用代称，不写真实网络标识。
- 浏览器取证留存页面文本、相关响应头或截图；截图前必须确认没有机密值、
  真实网络标识与账号名。

取证块使用以下格式：

```text
【命令原文】
<逐字保存命令>
【完整输出】
<逐字保存完整输出；失败同样保留>
【完整性对照】
<需要时写原文件、对照文件与两者的 SHA-256 哈希值>
【执行位置】
<写本机或经哪台代称机器执行>
```

## 人工保留面清单框架

以下子集永远不由 agent 代跑；具体条目由对应票补写。SAS 配对双屏比对指
配对过程中两台屏幕各自显示的配对信息由 owner 人工逐项核对。

### 机密测试值人工对照（#270 填写）

#### H-SEC-01 机密测试值事实来源与值不入证据

标注：操作面=owner 命令行；证据来源=真机端到端
前置数据：
- owner 在验收现场自己的密码管理器或私密记录中保存一份一次性测试值；本册与运行记录只记录该事实来源的代称，不记录值。
- 测试值至少包含中文、空格、引号、百分号、反斜杠与连字符，长度不小于 32 个字节，且不含换行。
- agent 只能拿到机密项名字、环境变量名与占位符，不能拿到值；owner 不得把值粘贴到对话、工单、命令参数、截图或运行记录。
- 依据：#55 结论第 1 条与票 #270 的取证要求。
执行步骤：
- owner 在不交给 agent 的本地终端中把测试值放入进程内变量，对三份证据文件做固定字符串检索：工具返回原文、审计查询输出、本地日志文件。
- 检索结论只写「未命中」或「命中」及文件名；不保存展开后的命令、测试值或命中行内容。
- owner 逐项人工确认运行记录和截图中没有测试值、真实网络标识与账号名。
期望结果：
- 三份证据文件均未命中测试值；若任一文件命中，该项验收失败，不得删改证据后重跑掩盖。
证据留存方式：
- 留存不含值的三份检索结论、owner 的事实来源代称、人工检查时间，以及每条机密项条目的 `masked` 名单或「无 `masked` 字段」记录；`masked` 名单指结构化输出里列出被输出遮蔽替换的机密项名字的字段。
是否允许自动化替代：
- 不允许自动化替代；测试值的事实来源与最终人工对照必须保留给 owner。agent 可以代跑产品步骤，但不能拿到测试值。

### 证书指纹人工比对（#271 填写）

#### 人工271-1 主机密钥或主机证书指纹人工比对

标注：操作面=owner 命令行；证据来源=真机端到端
前置数据：
- 依据 #45、#67 与 ADR 0011，准备一台一次性靶机和一个一次性服务器条目；
  owner 先在靶机本体控制台、虚拟化控制台或供应商页面取得主机密钥指纹。若
  执行现场提供的是 SSH 主机证书指纹，则以同一外部事实来源记录该证书指纹。
- 指纹的事实来源、取得时间和取得路径由 owner 私下记录；本册和运行记录只写
  来源类别，不写真实地址、账号或凭据。
- agent 可以准备靶机和命令，但不得代替 owner 判断两个指纹是否相同。
执行步骤：
1. owner 触发一次性条目的首次连接，让自动首次信任生成锚。
2. owner 在持有 vault 的机器执行 `sshmgr servers pin-hostkey <一次性条目>`，
   读取 `fingerprint`、`source`、`handshake` 与 `created` 字段。
3. owner 把输出中的 SHA-256 主机密钥指纹（或主机证书指纹）与第 1 步之前
   取得的带外事实逐字人工比对。
4. 比对一致时保留该锚供后续锚定转发验收使用；不一致时立即停止后续信任
   验收，执行 `sshmgr servers pin-hostkey <一次性条目> --clear` 清理错误锚，
   并把不一致作为失败证据登记。
期望结果：
- owner 记录「人工比对一致」或「人工比对不一致」；一致时 `source` 能说明
  锚的来源，`handshake` 与真实握手所用地址相符，但真实地址不出现在证据里。
- 不一致时错误锚被清除，后续条目不会继续使用这把锚。
证据留存方式：
- 留存 owner 命令原文、把真实地址替换为代称后的完整输出、人工比对结论、
  指纹事实来源类别和取得时间；需要清理时留存清理命令与完整输出。
是否允许自动化替代：
- 不允许。自动化测试只能证明显示值与存储值一致，不能替代「外部事实来源
  与呈现指纹是否相同」的人工安全判断。

### Windows 桌面手动添加引导目验（#272 填写）

#### 人工272-1 Windows 桌面手动添加引导与盘符可见性目验

标注：操作面=浏览器；证据来源=真机端到端
前置数据：
- 依据 #42、规格 #238 与 ADR 0008，在公司 A 的权威端登记一处只供验收
  使用的一次性 SMB 共享存储；共享密码使用专用的一次性挂载账号，并只授权
  这处共享。真实地址、账号名与密码只存在 vault 和 owner 的密码管理器里。
- 家 A Windows 新版客户端（工作机 1）的桌面会话尚未手动映射这处共享；
  owner 先确认资源管理器里看不到本条目使用的固定盘符。
执行步骤：
1. owner 在权威端 `/ui` 打开「共享存储」列表，进入这处共享的详情页，再
  点击「打开桌面手动添加引导」。
2. 在「这台电脑是拓扑里哪台设备」中选择工作机 1 对应的设备，点击
  「显示引导」。
3. 目验推荐地址、所属网络、固定盘符、访问路径、目录约定访问路径、
  Windows 手动映射步骤和等价命令
  `net use <盘符>: \\<地址>\<共享名> /user:<账号> * /persistent:yes`；
  确认页面写明命令里的 `*` 表示运行时输入密码。
4. 目验页面的「注意事项」：笔记本更换网络后映射可能失效；页面不显示、
  复制或下载共享密码，也不生成含密码的脚本，只提示 owner 输入自己保存
  在密码管理器里的密码。
5. owner 按页面步骤在工作机 1 的桌面会话手动映射盘符，输入自己保存的
  共享密码，写入并读取一个小文件；随后断开这个手动映射。
期望结果：
- 地址推算优先显示工作机 1 与提供方设备共同所在的物理局域网；页面步骤
  与登记的盘符、共享名、目录约定一致。
- 页面没有密码输入框、显示密码、复制密码或下载脚本入口，页面文本和
  截图中不出现共享密码。
- 手动映射前桌面看不到 sshmgr 在受管 Windows 服务器命令会话里注入的
  盘符；手动映射后桌面能访问共享；断开后不再留这个盘符。
证据留存方式：
- 留存脱敏后的页面文本或截图、owner 的目验结论、手动映射读写结论和
  断开清理结论；真实地址、账号名、密码与文件内容不得进入证据。
是否允许自动化替代：
- 不允许。桌面可见性、引导步骤是否足够清楚以及页面上没有密码入口，
  都是 owner 的人工视觉与安全判断；自动化测试只能代证页面字段契约。

### Web UI 基础页面浏览器与手机观感（#273 填写）

#### 人工273-1 基础页面手机观感

#### 权威端272-2 撤销、残留检查与换密码说明

标注：操作面=owner 命令行；证据来源=真机端到端
前置数据：
- 依据 #32、#42、规格 #212 与 ADR 0008，在公司 A 的权威端准备一个
  一次性共享和专用一次性挂载账号；使用三条一次性服务器条目：Linux 靶子、
  macOS 靶子和 Windows 靶子。三条条目都在挂载密码机密项的可写入服务器
  列表内。破坏性清理只允许作用于这些一次性靶子。
- Linux 与 macOS 靶子已由 `shares mount` 挂载；Windows 靶子已通过一次
  命令会话验证盘符可注入。owner 私下准备第二个人工输入的新共享密码。
执行步骤：
1. owner 用标准输入传入新的共享密码，执行
   `sshmgr shares revoke <一次性共享名> <一次性macOS条目> --unmount --new-password-stdin --yes`，
   保存输出中的换密码提醒与真正的撤销手段说明。
2. owner 在 macOS 靶机上核对 autofs 映射条目已删除、挂载已卸载、只留撤销
  标记；再执行 `sshmgr shares residue <一次性共享名>` 核对结论。
3. owner 执行
   `sshmgr shares revoke <一次性共享名> <一次性Linux条目> --unmount --yes`，
   保存版本号、远端清理结果与审计。
4. owner 在 Linux 靶机上核对 `/etc/fstab` 管理行和凭据文件已删除、挂载
  已卸载、只留下不含密码与地址的撤销标记；执行
   `sshmgr shares residue <一次性共享名>`，核对该靶子报告「仅有撤销标记」。
5. owner 执行
   `sshmgr shares revoke <一次性共享名> <一次性Windows条目> --yes`，
   核对命令不连接 Windows 服务器，并输出「各客户端同步快照后停止注入」、
   长期离线客户端的例外，以及「真正的撤销手段是更换共享密码」的说明。
6. 在新版客户端同步新快照后，agent 对 Windows 靶子执行一条引用固定盘符
   的命令；再等待超过快照保鲜周期后重复一次，核对两次都不再注入该共享。
7. owner 依次用 `shares unmount` 清理 Linux 与 macOS 靶子上的撤销标记，
   执行 `shares residue` 复查，再删除一次性共享、机密项、三条服务器条目
   与相关拓扑登记；保留全部清理输出。
期望结果：
- Linux 与 macOS 都是先删除持久配置、再写撤销标记、最后卸载；卸载成功后
  不会自动挂回，撤销标记只含编码共享名、版本号与撤销状态。
- 残留检查把 Linux 与 macOS 报为「仅有撤销标记」，把 Windows 服务器跳过
  并说明其上没有 sshmgr 持久配置；不可达靶子不会被排队成待清理清单。
- 换密码输出列出仍可挂载的 Linux 与 macOS 服务器，提醒它们要按新版本号
  重新挂载，也提醒桌面手动连接需要换密码；新密码不进入命令参数或证据。
- Windows 撤销只改登记，在线客户端同步后停止注入；输出如实说明长期离线
  客户端仍会继续注入，真正撤销靠更换共享密码。
证据留存方式：
- 留存每条命令原文与完整输出、Linux 与 macOS 靶机的配置删除证据、撤销
  标记的安全字段结论、残留检查输出、Windows 注入停止证据、审计查询
  `share-revoke`、`share-revoke-remote`、`share-unmount`、
  `share-residue-check` 与清理输出；不得保存新旧密码或真实地址账号。
是否允许自动化替代：
- 不允许。撤销是破坏性动作，必须在一次性真机靶子上验证实际配置删除、
  撤销标记、快照同步边界与清理结果；自动化测试不能替代这些证据。

  `sshmgr serve admin unlock 127.0.0.1` 能解除。

  失效。这两个时间边界由第 7 步测试代证。

- 留存浏览器页面文本、截图、响应头与 cookie 属性（不含 cookie 值）、每次
  登录耗时、锁定与解锁命令输出、审计查询输出、自动化测试完整输出；口令

  出原样留档。
是否允许自动化替代：
- 不允许自动化替代；#47 必须在真实 Windows 受管服务器上复设，不能用进程
  内假 SSH 服务器替代。

### 3.2 网络拓扑与主机信任（#271 填写）

是否允许自动化替代：

### 3.3 共享存储（#272 填写）

  提示只出现一次，并指出可能需要更新的服务器。

是否允许自动化替代：
- 不允许。真实权威端快照下发、客户端裁剪、快照保鲜与远端挂载必须真机

#### 客户端272-2 Windows PowerShell 与 cmd 会话内网络盘符注入

标注：操作面=agent 工具面；证据来源=真机端到端
前置数据：
- 依据 #42、规格 #205、票 #206 与 #288、ADR 0008，工作机 1 的一次性
  客户端实例可访问 Windows 受管服务器 A 的 PowerShell 服务器条目与 cmd
  服务器条目；一处一次性共享的固定盘符对两条条目都适用，挂载密码机密项
  的可写入服务器列表包含这两条条目。
- owner 确认两个服务器条目的默认 shell 分别是 PowerShell 与 cmd；NAS A
  已关闭「禁止同一 IP 多个连接」类限制。为认证失败演练准备一次性专用
  挂载账号，避免影响生产账号。
执行步骤：
1. agent 分别对两条 Windows 条目调用 `exec_context`，核对
   `planned_network_drives` 列出共享名与 owner 登记的固定盘符，
   `uninjected_network_drives` 为空。
2. agent 对 PowerShell 条目调用 `exec_command`，执行
   `Get-ChildItem <盘符>:\<子路径>`；对 cmd 条目执行
   `dir <盘符>:\<子路径>`。记录 `injected_network_drives`、用户命令输出

3. 在同一命令中分别读取当前进程命令行：PowerShell 条目执行

   `powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter 'name=''cmd.exe''' | Select-Object ProcessId,CommandLine"`。
4. owner 暂时把一次性挂载密码换成错误值；agent 同步客户端快照后，对
   PowerShell 条目连续调用两次 `exec_command` 执行只读命令，保存第一次
   认证失败警告与第二次「共享因认证失败已暂停注入」输出。
5. owner 把正确密码写回机密项；agent 同步新版本号后再调用一次命令，核对
   暂停自动解除、盘符重新注入且命令不被映射失败阻断。
6. 查询客户端本地 `cache-audit.log`，确认命令文本只含 agent 原命令，
   审计只记录注入共享名，不含地址、账号或密码。
7. 清理时撤销授权、同步客户端、删除两条一次性服务器条目与一次性共享、
  机密项和测试账号登记；保留清理输出。
期望结果：
- PowerShell 与 cmd 的每条命令都在同一个 SSH 登录会话内先由
  `WNetAddConnection2` 映射 owner 指定的固定盘符，用户命令能列出共享内容；

- 映射封装的内部状态行不出现在输出中；密码只经标准输入送达，不出现在

  测试代证。

#### 客户端272-3 共享地址中继本地拷贝、流式回退与重跑

   固定 `robocopy`；任务终态说明本地拷贝、半成品目录与从头重跑语义。
5. agent 以执行实例本地文件为源端、共享地址为目标端调用 `relay_file`，
   先不传 `via`，核对回退为 `mode="streaming_relay"`，
   `share_endpoint_server_id` 指向同在物理局域网的 Linux 条目 A；再用参数
   `via=<Linux条目B标识符>` 与新的一次性目标路径重跑一次，核对指定虚拟
   局域网端点覆盖自动选择。
6. agent 调用 `relay_file` 同时传 `from_share_address` 与
   `to_share_address`，保存完整报错「源端和目标端不能都是共享地址；请先
   用 query_topology 查询实际路径，再在可挂载共享的服务器上用
   exec_command 拷贝」。
7. 对第 2 步重新启动一次大文件本地拷贝，调用 `exec_stop(task_id)` 中途停止；
   确认目标端存在 `<目标>.sshmgr-partial` 且没有块清单；重跑同参数任务，
   核对输出说明从文件开头覆盖旧半成品，最终文件完整。
8. 在源端与目标端用 SHA-256 哈希工具比对最终文件；清理共享内文件、普通
   服务器文件、半成品、本地源文件与一次性登记，保留清理输出。
期望结果：
- 一端是共享地址且另一端可挂载时，`mode="local_copy"`；Linux 在已挂载
  服务器上执行固定 `cp`，Windows 在注入盘符的同一命令会话执行固定
  `robocopy`，文件字节不经执行实例内存。
- 另一端不可挂载时回退为流式中继；自动选择优先与提供方设备同在物理
  局域网且已实际挂载的 Linux 或 macOS 服务器，并列时按服务器名字升序；
   `via` 可以指定这样的端点，但不能用于已决定本地拷贝的普通服务器端。
- 两端都是共享地址直接报错；本地拷贝中断、停止或失败后不生成块清单、
  不能续传，重跑从文件开头覆盖旧半成品；完成后目标真名出现、半成品消失。
- 工具返回、任务输出与客户端本地 `cache-audit.log` 只有元数据，不含文件
  内容、共享密码、挂载账号或额外候选地址。
证据留存方式：
- 留存每次工具调用与任务轮询原文及完整输出、任务标识符、模式字段、
  端点服务器标识符、停止与重跑输出、源端与目标端 SHA-256 哈希、清理
  输出、本地 `cache-audit.log` 相关行；共享地址中的真实主机必须替换为

  另由自动化测试补充。

### 4.2 网络拓扑与主机信任（#271 填写）

#### 混跑271-1 旧客户端、新权威端的兜底锚与旧格式转发拒绝

标注：操作面=owner 命令行；证据来源=真机端到端
前置数据：
- 依据 #45、#67、规格 #132 与 ADR 0011，工作机 1 上的旧版本第二实例使用

  密钥锚定且兜底主机可达；条目 B 未锚定、兜底主机可达。
- 新权威端为条目 A 的快照推导旧格式兜底锚；两个条目的设备拓扑存在，但旧
  客户端版本不支持读取网络拓扑。
执行步骤：
1. 在旧版本第二实例执行 `sshmgr cache pull`，再执行
   `sshmgr ssh <条目A> <只读命令>`。
2. 在旧版本第二实例执行 `sshmgr ssh <条目B> <只读命令>`，触发旧格式首次
   锚定转发请求。
3. 查看新权威端 `serve` 服务日志中 `/pin-hostkey` 的状态行，并查询条目 B
   的锚与权威端审计。
4. 用源码测试补充旧格式请求契约：
   `go test ./internal/mcpserver -run '^TestPinHostkey_OldFormatRejected400$'`
5. 清理旧版本第二实例的一次性缓存、设备码、两个服务器条目和相关拓扑登记。
期望结果：
- 条目 A 照常只用兜底主机连接，导入的旧格式兜底锚校验通过；它得不到多地址
  选址能力，但也不能因新快照而失败。
- 条目 B 的旧格式转发请求缺少服务器条目标识，被新权威端以状态码 400 拒绝，
  并提示升级客户端；权威端没有为条目 B 落锚。
- 拒绝发生在发送登录凭据之前；服务日志和自动化测试均证明旧格式请求不会被
  猜测归属到某个条目。
证据留存方式：
- 留存旧客户端两条命令原文与完整输出、权威端服务日志状态行、条目锚显示、
  审计查询、自动化测试完整输出和清理输出；真实地址与账号必须打码。
是否允许自动化替代：
- 不允许用自动化测试替代。旧客户端二进制、新权威端推导的旧格式锚和真实
  兜底主机路径必须真机实证；请求形状契约可由第 4 步测试代证。

#### 混跑271-2 新客户端遇旧权威端的拓扑入口降级

#### 混跑272-2 新客户端遇旧权威端的共享入口降级

证据留存方式：

是否允许自动化替代：

#### 混跑275-3 新客户端遇旧权威端的降级、保鲜回退与通用工具

标注：操作面=agent 工具面；证据来源=真机端到端
前置数据：
- 依据 #30、#51 结论、规格 #222、ADR 0009 与 ADR 0014，工作机 1 上的旧版本
  第二实例作为一次性旧权威端运行；家 A Windows 新版客户端（工作机 1）的
  一次性实例已从它拉取不含推荐版本字段的快照。
- 旧权威端仍有一条一次性 Linux 受管服务器条目和一个可用的项目令牌；新版
  客户端的快照保鲜有效期设置为短暂的一次性值，便于在验收窗口内触发到期
  检查。混跑271-2 与混跑272-2 已覆盖拓扑与共享存储入口的详细报错。
执行步骤：
1. 记录两端实际版本号；确认新版客户端快照没有推荐版本字段，旧权威端的
   快照修订号查询接口对新客户端返回 404。
2. 启动 `sshmgr mcp --cache --instance <一次性实例>`，在快照过期后调用
   `list_servers`。保存旧权威端服务日志中的修订号查询与全量快照拉取状态，
   并在同一会话再调用两次 `list_servers`，保存三次工具返回。
3. 在同一 MCP 会话依次核对通用工具：`exec_command`、`exec_background`、
   `exec_output`、`exec_stop`、`upload_file`、`download_file`、
   `forward_port`、`close_port`、`relay_file` 与 `list_servers`。文件、后台
   任务和端口转发都使用一次性靶子，执行后立即清理。
4. 汇总混跑271-2 与混跑272-2 的证据编号，并补齐其中未执行的
   `sshmgr networks list --instance <一次性实例>`、
   `sshmgr devices show <一次性设备> --instance <一次性实例>`、
   `sshmgr devices probe --from self <一次性目标> --instance <一次性实例>`
   三个命令行出口。
5. 在候选发行版源码根目录执行：
   `go test ./internal/clientops -run '^TestMaybeLazyPull_Version404FallsBackToFullPull$'`
   与
   `go test ./internal/cli -run '^(TestSnapshotPollE2E_OldAuthorityStopsPolling|TestCacheVersionE2E_ToolHintComparesVersions)$'`。
6. 清理新版一次性实例、旧权威端一次性实例与全部临时授权、文件、任务和端口
   转发，保存清理输出。
期望结果：
- 网络拓扑与共享存储的专用入口统一返回「权威端版本过旧，不支持网络拓扑与
  共享存储，请先升级权威端」；它们在发起目标 SSH 连接、挂载前保鲜或读取
  数据前就返回，不误报数据不存在。
- 通用工具全部照常经兜底主机工作，不因旧权威端额外报错；`relay_file` 两个
  端点都使用常规服务器路径，不要求共享存储识别。
- 快照保鲜回退到到期全量拉取；首次修订号查询 404 后停止修订号轮询，后续
  到期检查不再反复请求修订号接口。
- 同一 MCP 会话第一条工具结果附一次「客户端比权威端新，建议先升级权威端」，
  后续工具结果不重复提示；原有结构化结果保持可用。
证据留存方式：
- 留存两端版本号、快照状态、服务日志状态行、三类工具调用原文与完整输出、
  三个命令行出口输出、两条自动化测试完整输出、清理输出；真实地址与账号名
  必须脱敏。
是否允许自动化替代：
- 不允许。新旧二进制、真实缓存格式、真实服务日志和工具注册面必须在版本
  混跑真机上核对；保鲜回退、停止轮询和会话内提示去重可由第 5 步测试代证。
