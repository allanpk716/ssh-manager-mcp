# 桥热升级(v0.20.0)真机验收册

覆盖:v0.20.0 桥热升级(机制与取舍见 [ADR 0006](../adr/0006-bridge-hot-upgrade-self-demote-pump.md);词汇见仓库 CONTEXT.md「桥与热升级」)。验收对象=宿主机器上的桥(直连/缓存两形态;权威端 serve 无本功能改动)。

## 前置条件(全项通用)

- 盘上已装 v0.20.0 及以上。
- 测试升级推荐 `sshmgr update --file <包> --sha256 <hex>`:用**同一份代码、仅版本戳不同**的两个构建做「打底版→目标版」,避免污染真实版本序列(注意:同版本重装会被拒绝——见 D1,这本身是护栏)。
- 「真实宿主」= 真的 Claude Code 会话:agent 代跑用无头模式(stream-json 多轮驱动,范本见运行记录);owner 人工跑用交互会话。

## 验收项

### A1 空闲自动热升级(真宿主)

- 步骤:开无头真实会话 → 调 `reload_self` 记下 `version` → 外部 `sshmgr update`(落新代际信号)→ 不做任何操作,等一个轮询周期(约 30 秒)→ 再调 `reload_self`。
- 取证:两次 `reload_self` 的完整 JSON;进程谱系(按创建时间列 `sshmgr.exe`,继任的出生时间应落在 update 后一个周期内)。
- 判据:第二次应答 `version`=新版本(应答者已是继任进程)、会话连接不断、工具照常可调。

### A2 工具触发换手与应答时序

- 步骤:落新代际后**立即**(一个周期内)调 `reload_self`,紧接着再调一次。
- 判据:第一次返回 `handover=started` 且含 `successor_version`(注意该响应的 `version` 仍是旧版本——它由发起换手的旧进程写回);第二次 `version`=successor 版本。

### A3 忙时拒绝

- 步骤:会话内 `forward_port` 开一条真隧道 → `sshmgr update`(落新代际)→ 调 `reload_self`;忙窗(隧道在飞)跨多个轮询周期后再观察;`close_port` 后再调。
- 判据:`handover=declined_busy` 且 `busy.active_tunnels>=1`,不换手;忙窗内自动换手持续跳过不误切;关隧道后完成换手。

### A4 多实例独立

- 步骤:两会话(不同实例或不同形态)并行,先后落两次代际信号。
- 判据:各自换代成功、互不串扰;与同机其他会话的桥并存无扰(进程谱系佐证)。

### A5 继任崩溃收场

- 步骤:定位该会话的进程链(泵=链上最老的 `sshmgr.exe`,继任=最新)→ `taskkill /F` 杀继任。
- 判据:泵随之退出(管道 EOF 收场,**零孤儿进程**);宿主侧表现为该 MCP 服务断供——无头模式实测为下次工具调用自动重拉桥(优于设计预期);交互会话走 `/mcp` 重连恢复。

### A6 降级传播

- 步骤:`sshmgr update --version <旧tag>`(或 `--file` 旧版本包)→ 调 `reload_self`。
- 判据:照样换手,`disk_version`=旧版本号(代际只看先后、不比版本大小)。

### D0 doctor update-gen 行

- 判据:有效信号=PASS(代际+版本+时间);文件缺失=INFO(「无信号」);损坏=WARN+修复提示;全程零网络。

### D1 同版本重装护栏

- 判据:`update --file` 与已装版本相同的包被拒绝(「已装该版本」),盘上不动。

## 人工保留面

交互式宿主的一次性 `/mcp` 重连「上车」动作(引导物理事实:≤v0.19 的在飞会话没有换手代码;此后一切自动)。无感官判断项。
