# 票 03 · 换手核心库(领养启动/就绪协议/泵/回退,独立可测)

## What to build

新包 `internal/mcpserver/hotswap`,实现与具体工具注册面解耦的换手核心:

1. **领养模式启动器**:组装环境变量前缀 `SSHMGR_HOTSWAP_*`(已协商 MCP 协议版本、宿主能力、桥形态与实例参数等会话参数)与 `SSHMGR_HOTSWAP_READY`(就绪文件路径);按代次接线——首代:父侧新建一对**泵侧管道**,继任子进程的标准输入输出接泵侧管道两端(不接触父侧持有的宿主侧句柄),标准错误接父侧同流;后续代:继任的标准输入输出**直接继承**父进程当前的标准输入输出句柄。
2. **就绪协议**:继任完成初始化后写就绪文件(含版本);父侧轮询,超时 15 秒判失败。
3. **泵**:宿主侧句柄 ↔ 泵侧管道双向字节搬运;泵侧读 EOF 或写失败→泵退出;宿主侧句柄关闭→关闭泵侧管道(继任读标准输入 EOF 自行退出,不用进程句柄杀)。
4. **回退语义(库层)**:就绪超时/失败→不进入退位,返回失败与原因,父侧自身状态不变。
5. **退位前应答钩子**:退位/退出前先执行回调(供上层把发起调用的应答写回)。

规格依据:spec.md 实施决策第 3 条(D1/D8/F4/F5)。

## 验收标准

- [ ] 管道对回环:完成一次「拉起→就绪→泵化」后,双向字节透传无损(内容比对)
- [ ] 继任就绪超时(伪造不写就绪文件的继任)→调用方收到失败与原因,自身管道状态不变(可继续读写)
- [ ] 泵侧写失败(伪造对端关闭)→泵退出
- [ ] 宿主侧读端关闭→泵侧管道被关(继任可观察到标准输入 EOF)
- [ ] 后续代:第二个继任接管同一泵侧管道、第一继任退出后,泵仍正常透传
- [ ] 退位前应答钩子被调用且先于泵化/退出
- [ ] `go test ./internal/mcpserver/hotswap/` 全绿
