# 票 05 · 后续各代换手与跨代泵透明

## What to build

后续各代换手闭环:当前桥(已被领养,标准输入输出=泵侧管道)再次发现新代际时,以**继承句柄**方式拉起下一代继任、就绪后应答写回并退出;泵对端点换人无感知。覆盖完整失败面与降级:第二代及以后的继任在服务中途死亡→泵经泵侧管道 EOF/写失败退出(宿主侧表现为掉线,与现状桥崩溃一致);盘上代际变旧(降级信号,`update --version` 场景)同样触发换手。

规格依据:spec.md 实施决策第 3 条后半(D1/D12/D8)。

## 验收标准

- [ ] 三代链端到端:首代泵化→二代接管→二代再换三代(继承句柄)、二代退出、泵全程存活透传,宿主侧帧序无损
- [ ] 服务中途杀死二代继任→泵退出(伪宿主观察到连接终止,行为同桥崩溃)
- [ ] 盘上代际较出生代际**变旧**(降级)→同样触发换手(不比版本字符串)
- [ ] 二代换三代时,二代对 reload_self 的应答先写回再退出(伪宿主能读到该应答)
- [ ] `go test ./internal/mcpserver/ -run 'HotSwap|Gen'` 全绿
