# 桥热升级(Bridge Hot Upgrade)规格

> 术语依 CONTEXT.md「桥与热升级」:桥=宿主机器上被 AI agent 宿主拉起的标准输入输出(stdio)形态 MCP 服务进程;泵=热升级后留在最外层只双向搬运字节的哑进程;会话领养=继任进程接手已与宿主完成握手的会话。决策出处:.xcheck/20261008-175335/(decisions D1-D17、FINDINGS F1-F5);机制取舍见 docs/adr/0006(工作区随批)。

## Problem Statement

sshmgr 发布新版本后,正在使用 MCP 工具面的会话拿不到新版本工具:工具清单编译期静态注册,桥随宿主进程生灭,`sshmgr update` 换掉磁盘二进制后运行中的桥继续旧代码(更新分支注释原话「运行中的桥继续旧版」)。要用手动段,就得重启宿主(如 Claude Code)或对单个服务手动重连——正在进行的任务被打断。

## Solution

桥在空闲且磁盘上存在新代际二进制时,自动完成换手:以领养模式拉起继任进程、交接已握手的会话,自己退位;退位后最外层留一个泵(纯字节搬运),宿主看到的进程始终活着、连接不断。继任接管后发一次工具清单变更通知,支持该通知的宿主(含 Claude Code)在**当前会话**立即拿到新工具。另提供 reload_self 工具:查询当前/磁盘/最新版本,并可在空闲时强制触发换手。取新二进制永远只经 `sshmgr update` 既有校验链,换手路径零网络取码。

## User Stories

1. 作为正在使用 sshmgr 工具面的 agent 会话,我想要 owner 更新磁盘二进制后,不重启宿主就立即用上新增的 MCP 工具,以便不中断正在进行的任务。
2. 作为 agent,我想要一把 reload_self 工具,查询当前进程版本/磁盘代际与版本/GitHub 最新版,并在空闲时主动触发换手,以便自行发现并消除版本落后。
3. 作为 owner,我想要存在活跃隧道、运行中后台任务、进行中传输或未答请求时,换手被拒绝并返回活跃清单,以便远程操作不被升级打断。
4. 作为 owner,我想要继任进程起不来时旧桥继续服务并返回失败原因,以便升级失败不影响在用会话。
5. 作为 owner,我想要降级(`update --version` 旧版本)同样传播到在飞桥,以便坏版本一键回滚。
6. 作为 owner,我想要继任崩溃或宿主退出时泵干净收场(宿主侧表现为与今天桥崩溃一致的掉线,手动重连可恢复),以便失败路径不劣于现状。

## Implementation Decisions

1. **代际信号文件**:`sshmgr update` 在替换成功点于**二进制同目录**写 `sshmgr.update-gen`(JSON:gen=单调递增时间戳、version、time;写入前刷盘)。可写性由自更新替换 exe 同一前提保证;每安装一份二进制一份信号,多实例共用同盘信号。桥启动时快照「出生代际」,此后定期(约 30 秒)比较盘上代际——**不比版本大小**,降级同样触发;文件缺失/损坏=无信号不动。(D9/D12)
2. **忙判据**:活跃隧道>0,或运行中后台任务>0(终态保留期不算),或进行中传输>0,或在飞未答请求>0(**豁免发起换手的本次调用**)。忙时:工具触发返回活跃清单,自动触发静默跳过下轮再试。(D5/F3)
3. **换手核心(独立库,不依赖具体工具注册面)**:
   - **领养模式启动**:环境变量前缀 `SSHMGR_HOTSWAP_*` 传递会话参数(已协商 MCP 协议版本、宿主能力、桥形态与实例参数);`SSHMGR_HOTSWAP_READY` 指定就绪文件,继任完成自身初始化后写入;父桥轮询就绪,**超时 15 秒判失败**。
   - **首代换手**(桥的标准输入输出还直连宿主):父桥新建一对泵侧管道;继任的标准输入输出接泵侧管道、**不接触宿主侧句柄**;标准错误流接父桥同流(宿主可见日志不换轨)。就绪确认后,父桥**先把发起调用的应答写回,再在消息边界**停止解析、化为泵:宿主侧句柄 ↔ 泵侧管道双向搬字节。(F5)
   - **后续各代换手**(当前桥的标准输入输出对面已是泵侧管道):继任**直接继承**当前桥的标准输入输出句柄;应答写回后当前桥退出;泵对端点换人无感知。
   - **回退**:继任就绪判定失败→父桥不退位,继续以服务进程应答,返回失败与原因。(D8)
   - **泵收场**:泵侧管道读 EOF 或写失败→泵退出(继任死亡,宿主侧掉线,人工 `/mcp` 重连,同现状);宿主侧句柄关闭→泵关闭泵侧管道,继任读标准输入 EOF 自行退出。(F4)
   - **清单变更通知**:继任接管后无条件发一次 `tools/list_changed`(清单没变也无害)。(D3)
   - **会话领养的 SDK 缝**:MCP 服务端需以「已握手」状态起服务(注入协议版本与能力);若所用 Go SDK 无现成入口,在接入层实现领养注入。验收以伪宿主端到端行为为准,不绑定 SDK 内部 API。
4. **reload_self 工具**(工具面第 14 把):无参数;返回当前进程版本、盘上代际与版本、GitHub 最新版本(仅被调用时联网查一次,复用自更新发现逻辑的只读部分);盘上有新代际时执行换手(含忙检查)并返回结果;忙时返回活跃清单。本工具与换手全路径**零网络取可执行代码**。(D13/D7/D11)
5. **多实例**:同一台机器多把桥各自记出生代际、各自独立换血,无共享内存状态。
6. **doctor(可选)**:新增「盘上代际」行,只读信号文件,零网络。
7. **引导**:不改任何宿主注册;机制发布后新拉起的桥即新版;升级正开着的会话需一次 `/mcp` 重连(发布说明明示)。不做旧桥迁移。(D6)

## Testing Decisions

- **单元**:信号文件写读(含缺失/损坏/单调性)、忙计数(隧道/任务/传输/在飞,豁免指定调用)、领养参数组装与解析、就绪超时。
- **集成(伪宿主,黑盒)**:进程内管道对模拟宿主;继任用测试二进制再执行模式构造(仓库既有跨进程测试先例:internal/cli/multiinstance_e2e_test.go 的双实例语义测试)。覆盖:两代与三代换手帧序完整、清单变更通知发出、忙时拒绝+清单、继任失败回退不退位、泵在继任死亡/宿主退出两向收场、降级信号传播、双实例并行换血互不干扰。
- 只测外部行为,不测内部函数;**真实宿主(Claude Code)行为不自动测**,列入人工验收建议条目(当前会话新工具可用/忙拒绝/掉线重连恢复),供验收册登记。

## Out of Scope

- 宿主注册形态变更;复活远程 MCP 面;无人值守网络自动升级;权威端 serve 的升级路径;在飞旧桥迁移。
- CONTEXT.md 词条与 docs/adr/0006 的提交:工作区遗留的同批设计文档,由 owner 随合并自行提交(夜链分支不捎带)。

## Further Notes

- 已知宿主小坑:同一轮对话中途注册的新工具可能报「无此工具」,下一轮恢复;reload_self 工具描述提示重试。
- Windows 语义依赖:0/1/2 号句柄继承原生支持(3 号及以后附加句柄不可用,本设计不需要);运行中 exe 可改名不可删(自更新已依赖同一语义)。
- 发布建议:机制首次上车的版本说明中写明引导措辞(现开会话需一次 `/mcp` 重连,此后永久自动)。
