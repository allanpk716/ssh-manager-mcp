# 定时口令加密备份 + TUI 备份页 — 实施 spec

> 来源:Plan 49 design spec rev1(评审收敛版,.xcheck/20260929-115645/proposal.md);决策快照 D1–D10 同环 decisions.md;术语遵 CONTEXT.md(备份/备份配置/口令文件);架构决策见 docs/adr/0004-encrypted-local-dir-backup-owner-managed-replication.md。

## Problem Statement

生产 vault(NUC10 权威端)当前没有任何在跑的备份:代码有两条既有备份路(口令加密的 export/import 与明文 NAS 的 backup create),但部署为零。owner 给定的备份目标是本地目录 + 自管群晖同步,该形态踩破明文备份的全部部署硬约束(远端 tailnet 媒体共享 + 自管同步机制),按既有纪律必须走加密路线。同时备份只能靠命令行 + 手配计划任务,无任何可视面。

## Solution

把「备份」做成一条统一链路:一份**备份配置**文件(vault 目录下的 backup.json:备份目录/保留份数/口令文件路径)作为唯一事实源;`backup create` 命令新增**加密模式**(口令文件在场即加密),产出与 export 同构的口令加密文件(`.sme`),内建跑前口令世代校验、写后解密验证与按扩展名轮转;`backup verify` 支持解密级校验;broker TUI 新增第 6 页「备份」(状态展示 + 立即备份 + 校验 + 改配置,三道保存校验);定时调度由部署期一次性安装的计划任务(SYSTEM 账户、未登录照跑、错过补跑)驱动同一命令。恢复复用既有 `import` 原路,设备码按既有语义重新发码入网。

## User Stories

1. 作为 owner,我想用一条命令把整个 vault 备份成口令加密文件,以便机器损坏时凭口令在任何机器恢复。
2. 作为 owner,我想让备份每天定时自动发生而无需我登录,以便凌晨无人值守也有当天备份。
3. 作为 owner,我想让备份自动只保留最近 N 份(默认 30)并删更旧的,以便备份目录不无限增长。
4. 作为 owner,我想把备份目录/保留份数/口令文件路径写在一个配置文件里,以便计划任务、TUI、手工命令三个入口共用同一套事实源,不被旗标覆盖时打架。
5. 作为 owner,我想让程序拒绝把口令文件配进备份目录子树,以便口令永远不会跟着密文被同步到群晖。
6. 作为 owner,我想在口令换了导致旧备份解不开时得到明确报错并停跑,而不是继续写新备份,以便不会到灾备当天才发现旧备份全废。
7. 作为 owner,我想校验一份备份文件是否完好,以便在依赖它之前确认没坏。
8. 作为 owner,我想在 TUI 里看到备份文件列表与新鲜度(超 25 小时警示),以便调度没跑一眼看出。
9. 作为 owner,我想在 TUI 里点一下就立即备份或校验最新一份,以便不记命令也能操作。
10. 作为 owner,我想在 TUI 里改备份配置且受与命令行完全相同的校验,以便两个入口行为永远一致。
11. 作为 owner,我想用既有的 `import` 命令恢复加密备份,以便恢复路径零新增学习成本(恢复后设备码按既有语义逐台重新发码)。
12. 作为 owner,我想让不带口令的既有明文备份用法逐字节不变,以便其他满足其硬约束的部署不受影响。

## Implementation Decisions

- **备份配置(backup.json)**:三字段全必填(dir/keep/passphrase_file),两路径字段均须绝对路径;**口令文件位置不变式:passphrase_file 不得位于 dir 子树内**(路径规范化后前缀判定),`--config` 加载与 TUI 保存双侧 fail-closed 报错拒绝;旗标 > 配置 > 默认的取值优先级;调度时刻不属它管。
- **backup create 加密模式**:判定 = 口令文件在场(直连旗标或经配置);产物 `vault-<UTC时间戳>.sme`(沿用既有 prefix 与同秒 `-2/-3` 后缀机制);封装 = 既有快照 JSON → 既有口令加密信封(Argon2id+AES-256-GCM,SSHMGRV1);**跑前口令世代校验**(dir 已有 .sme 时先试解密最新一份,失败报错退出不写);无"无变化跳过"(密文每次必不同);写后验证 = 重读+试解密+重解析;轮转按扩展名(.sme 与 .json 各自独立,同目录混放互不误删);marker/`.git` 防线/并发锁/原子写全部复用既有实现。
- **backup verify 扩展**:`.sme` + 口令文件 → 解密级校验(解密+重解析两关);无口令对 .sme 明确报需口令;明文分支不变。
- **TUI 第 6 页「备份」**:仅 broker/standalone 角色构造(客户端角色不显示);状态区 = 配置摘要/备份文件列表(时间倒序,最近 10+总数)/新鲜度健康色/计划任务只读探测(已装/未装);动作 = [b] 立即备份(后台跑同一条 create 逻辑)、[v] 校验最新(试解密+重解析)、[e] 编辑配置(huh 表单三字段);**[e] 保存前三道校验**:①两路径字段绝对路径 ②口令文件子树禁入 ③dir 已有 .sme 时口令试解密最新一份,任一失败阻断保存;配置缺失时整页引导态仅 [e] 可用;失败呈现措辞按实现裁量,不强制三分(评审 F9 留档)。
- **调度(部署期,非程序面)**:计划任务 SYSTEM 账户、未登录照跑、StartWhenAvailable 错过补跑、10 分钟强停、电源不唤醒;程序与 TUI 均不提供装/卸。
- **口令文件(backup.pass)**:部署期程序外生成(强随机 ≥32 字符);**显式设置 DACL**(仅 SYSTEM/Administrators/当前用户、禁继承——目录继承已被真机证伪),icacls 输出记入验收;离机副本(1Password)为硬性运营前提。
- **格式零新增**:与 export 产物逐字节同构;向后兼容承诺(version ≤ 当前可读),不承诺旧版读未来新版。

## Testing Decisions

只测外部行为,不测实现细节;沿用仓库既有测试先例(internal/cli 的表驱动测试与临时目录 vault 夹具、internal/tui 的契约测试与页面测试基建):

1. 加密模式:产物以 SSHMGRV1 开头;marker/.git/锁/原子写路径;同秒连跑沿用后缀机制不覆盖;
2. 轮转:.sme 保留 N 份;同目录 .json/.sme 混放互不误删;
3. 写后验证:篡改一字节→失败;口令错→失败;
4. 配置:正常读入;字段缺失/相对路径/坏 JSON/口令文件在 dir 子树,各自 fail-closed;旗标覆盖优先级;
5. 跑前世代校验:有旧 .sme+口令不符→报错不写;空目录→正常跑;
6. **往返等价**:create 加密产物 → import → 条数字段全等(钉死格式等价承诺);
7. verify:.sme 带口令(完好/篡改两分支)与不带口令三分支;
8. TUI:未配置引导态、列表刷新、[b]/[v]/[e] 分发、[e] 三道校验各失败分支、角色门控(client 不显示第 6 页);
9. 回归:无口令时全部既有明文测试不改一行照绿。

## Out of Scope

- 调度器装/卸/管理(部署期一次性,runbook 承担);
- 明文 NAS 模式任何行为变更;
- 增量/事件触发备份;多 owner/多人分持;程序内触达群晖;
- 客户端角色 TUI 备份界面;
- 未采纳的评审留档项(F6 前向兼容措辞/F9 校验文案三分/F11 直连旗标合并后复查/F12 TUI 重写后 DACL 重设)——owner 晨报拍板后再议,本轮不实现。
